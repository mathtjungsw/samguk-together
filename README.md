## 실행과 배포

Node.js 24와 npm을 사용합니다.

```sh
npm ci
npm run dev
```

`http://localhost:4190`에서 엽니다. `npm run dev`는 시작할 때 한 번 빌드합니다. 수정 후 `npm run build`하고 새로고침하면 반영됩니다.

```sh
npm test
npm run test:rules
npm run build
```

보안 규칙 검증에는 Java 21 이상이 필요합니다. Windows의 공통 설치 경로는 `C:/Users/codex/.codex/skill-runtimes/firebase-java/jdk-21.0.9+10-jre`입니다. `JAVA_HOME`과 PATH를 지정하여 사용합니다. `test:rules`는 실제 전장 대신 `demo-samguk-online` 에뮬레이터만 사용합니다. 에뮬레이터가 이미 실행 중이라면 `node --test tests-rules/*.test.mjs`를 사용합니다.

`main`에 푸시하면 GitHub Actions가 규칙·저장·채팅 검증과 빌드를 수행한 다음 `dist/`를 GitHub Pages에 배포합니다. Firebase 규칙은 사이트 배포와 별개입니다. 변경 시 `node tools/generate-rules.mjs`로 생성하고 에뮬레이터 검증 후 Firebase Console에 게시하거나, Firebase CLI 로그인 후 `npx firebase deploy --only database --project samguk-together`로 반영합니다. 사이트 배포에 관리자 키나 서비스 계정은 필요하지 않습니다.

`firebase-config.json`은 브라우저용 공개 연결 정보입니다. 서버 관리자 비밀키를 넣지 않습니다. 데이터 접근 권한은 `firebase.database.rules.json`이 제한합니다. Google 로그인 허용 도메인은 `localhost`, `samguk-together.firebaseapp.com`, `samguk-together.web.app`, `mathtjungsw.github.io`입니다.

- 전체 채팅은 기본 최근 5개, 열면 최근 50개입니다. 서버에는 50개 슬롯만 저장하며 이전 메시지를 교체합니다. 메시지는 200자, 1초당 1개입니다.

## 저장 구조와 운영 범위

`worlds/main`에 공통 전황, `chat/global`에 전체 채팅을 저장합니다. 변경된 경로만 한 번에 저장하며 전황 버전 검사를 통해 동시 쓰기를 감지합니다. 다른 영토의 명령과 충돌하면 최신 전황으로 최대 6회 재시도하고, 선택한 공격 영토 자체가 바뀌면 재선택하도록 알립니다. 같은 명령의 재전송은 중복 반영하지 않습니다. 전황과 중복 방지 기록은 각 100개입니다. 한 기기의 명령과 채팅은 순서대로 보내 SDK 내부 트랜잭션이 서로 취소되지 않게 합니다.

충원은 기준 시각과 고정 난수, 충원 예정 시각·영토 ID의 일정한 처리 순서로 계산합니다. 최소 한 접속자가 활동 중이면 필요한 때만 전체 영토의 충원을 묶어 정산하며, 모두 미접속이면 다음 접속에서 경과 시간을 반영합니다. 매초 서버에 쓰거나 상시 실행되는 충원 서버를 사용하지 않습니다. 새 장수 사건과 시스템 채팅은 전황 변경과 같은 다중 경로 갱신으로 모두 저장하거나 모두 재시도합니다. 이미 정산된 충원은 다시 쓰지 않습니다. 화면의 경과 시간은 Firebase 서버 시차를 적용합니다. 연결이 끊기면 공격과 채팅 전송을 막습니다.

기존 전황의 `version: 1`을 보존하고 `featureVersion: 4`, `rosterVersion: 2`, `effectsVersion: 1`, `rolePolicyVersion: 1`, 통계와 군주 생존 ID를 추가합니다. 새 화면은 이관 전 잠시 대기하며, 새 규칙 게시 후 구버전 화면의 쓰기를 차단해 통계와 명단 이관이 되돌아가지 않게 합니다. 업데이트 후 열려 있던 화면은 새로고침해야 합니다. 운영 전황 백업에는 참가자 기록이 들어 있으므로 저장소에 커밋하지 않습니다.

주사위 판정은 공격자의 기기에서 처리합니다. Firebase는 Google 로그인, 소유권, 명령 범위, 명령 시각, 전황 버전, 자료 형태 등을 검사합니다. **지인 간 신뢰를 전제로 하며 클라이언트 코드를 변조하는 참가자의 주사위 조작까지 막는 구조는 아닙니다.** Google 계정 여러 개를 사용하는 행위도 자동으로 막지 않습니다. 서버 권위 판정이나 참가자 초대 제한이 필요해지면 별도 개발합니다.

무료 한도 내 운영을 목표로 하며 유료 결제 계정을 연결하지 않았습니다. Spark 한도를 넘으면 서비스가 제한될 수 있습니다. 실제 10~15명 장기 플레이의 트래픽·게임 균형은 운영하면서 확인해야 합니다. 자동 검증에는 게임 규칙과 지도 연결 관계, Firebase 저장·권한·경합·채팅이 포함됩니다. 에뮬레이터 테스트는 실제 여러 사람의 기기·계정 접속 시험과 구분합니다.
