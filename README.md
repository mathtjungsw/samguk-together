- 기존 소유 장수 중 새 명단에서 제외된 이름은 같은 D등급의 다른 장수로 자동 교체합니다. 병력 수·ID·등급·행동 대기·영토와 군주 이름은 보존하고, 교체를 새 충원으로 알리지 않습니다. 전장 전체에서 살아 있는 이름은 중복하지 않습니다. 같은 등급의 빈 이름으로 교체한 뒤 초과 병력은 이름 없는 동급 병력으로 보존하고 고유 효과는 부여하지 않습니다.
- 랭킹은 영토·병력·처치·전사를 기준으로 정렬합니다. 기본 순서는 영토 → 병력 → 처치이며 같은 값은 공동 순위입니다. 처치·전사는 **기존 전장의 새 버전 전환 시점부터** 누적하며 재참가 후에도 유지합니다. 중립 수비병 처치도 포함합니다.
- D8·D12 충원과 D20 군주 부활은 접속자 전체 알림·전황·‘전령’ 시스템 채팅으로 공유합니다. 사용자 대화와 시스템 소식을 합쳐 서버에는 최신 50개 채팅만 남깁니다.
- D20이 전사했고 영토가 남아 있으면 내 영토에서 ‘군주 살리기’를 선택합니다. 그 영토에서 행동 가능한 D4·D6·D8·D12의 **면수 합계 20 이상**을 소모해 D20 1명과 교환합니다. 초과 비용은 반환하지 않습니다. 예: D12+D8, D8+D6+D6, D4 다섯 명. 교환한 병력은 전사 통계에 넣지 않습니다.
- 부활은 해당 영토의 행동 1회입니다. 영토와 부활한 군주는 10분을 기다리며 새 시작 보호는 생기지 않습니다. 살아 있는 자기 D20이 있거나, 마지막 영토를 잃었다면 부활할 수 없습니다.
- 적용한 업데이트의 전체 공지는 전황·전체 채팅에 한 번 기록합니다. 여러 사람이 동시에 접속해도 같은 공지를 중복 전송하지 않습니다. 처음 보는 기기에는 완료 알림도 표시합니다.

- 100명 모두 고유 효과를 갖습니다. 영토당 내정 담당 1명, 전투 특기 최대 2명을 자동 배정합니다. 효과 설명·남은 대기·현재 위치는 ‘내 장수’와 ‘무장 100인’에서 확인합니다. 내 장수 목록에서 인접한 내 영토로 바로 이동할 수 있습니다.
- 포화된 목적지로 D6·D8·D12·D20을 옮길 때 대기 중 D4와도 서로 자리를 바꿀 수 있습니다. 장수만 이동하면 개인별 이동 대기 10분을 적용하며 병력 수·ID·효과 상태를 보존합니다. D4만 이동한 소식은 전황에서 제외합니다.
- 기본 공격 점수에 무장 효과를 적용합니다. 진영별 이익 최대 +10점, 장수별 최대 +8점, 적 효과 감점 최대 6점입니다. 예상 승률은 같은 효과 계산을 사용하는 작업 스레드에서 8,192회 추정하며 ‘약’으로 표시합니다. 탈출·희생·성장은 실제 전투 결과로 처리합니다.
- 최초 이관에는 기존 기록을 백업하고 이전 충원을 먼저 정산합니다. 운영 백업은 비공개 로컬에만 보관하며 채팅은 덮어쓰지 않습니다. 이번 자료는 자동 담당·개인 이동 대기를 포함한 v4 형태로 저장합니다.

개발 범위와 검증 계획은 [DEVELOPMENT_PLAN.md](./DEVELOPMENT_PLAN.md), 최초 제안과 변경 결정은 [IMPROVEMENTS.md](./IMPROVEMENTS.md)에 있습니다.

## 실행과 배포

Node.js 24와 npm을 사용합니다.

```sh
npm ci
npm run dev
```

`http://localhost:4190`에서 엽니다. `npm run dev`는 시작할 때 한 번 빌드합니다. 수정 후 `npm run build`하고 새로고침하면 반영됩니다.

```sh
npm test
npm run test:rules
npm run build
```

보안 규칙 검증에는 Java 21 이상이 필요합니다. Windows의 공통 설치 경로는 `C:/Users/codex/.codex/skill-runtimes/firebase-java/jdk-21.0.9+10-jre`입니다. `JAVA_HOME`과 PATH를 지정하여 사용합니다. `test:rules`는 실제 전장 대신 `demo-samguk-online` 에뮬레이터만 사용합니다. 에뮬레이터가 이미 실행 중이라면 `node --test tests-rules/*.test.mjs`를 사용합니다.

`main`에 푸시하면 GitHub Actions가 규칙·저장·채팅 검증과 빌드를 수행한 다음 `dist/`를 GitHub Pages에 배포합니다. Firebase 규칙은 사이트 배포와 별개입니다. 변경 시 `npm run rules:generate`로 생성하고 에뮬레이터 검증 후 Firebase Console에 게시하거나, Firebase CLI 로그인 후 `npx firebase deploy --only database --project samguk-together`로 반영합니다. 사이트 배포에 관리자 키나 서비스 계정은 필요하지 않습니다.

`firebase-config.json`은 브라우저용 공개 연결 정보입니다. 서버 관리자 비밀키를 넣지 않습니다. 데이터 접근 권한은 `firebase.database.rules.json`이 제한합니다. Google 로그인 허용 도메인은 `localhost`, `samguk-together.firebaseapp.com`, `samguk-together.web.app`, `mathtjungsw.github.io`입니다.

## 게임 규칙

- 역사 지명·위치를 참고한 90개 영토. 비단 지도와 성곽 표식으로 표시하며, 변을 공유하면 인접하고 최대 인접 5곳입니다. 장식과 경계 표현이 달라져도 연결 관계는 그대로입니다. 강·산 표시와 지형 보정은 없습니다.
- 중립 중 무작위 영토에서 D20 군주 1명과 D4 병사 4명으로 시작합니다. 중립이 없으면 영토 수 1위의 무작위 영토를 승인 없이 배정합니다. 공동 1위는 추첨하며 기존 병력은 원주인의 다른 영토로 복귀하거나 복귀 대기 상태로 보존됩니다.
- 병력은 D4 병사, D6 부장, D8 장수, D12 장군, D20 군주입니다. 군주는 플레이어 본인이며 100명의 무장은 소속 구분 없이 등장합니다. 초상은 이 게임을 위해 제작했습니다.
- 소유 영토마다 미접속 중에도 10분당 1명 충원합니다. 시즌5까지는 D4 90%, D6 7%, D8 2.5%, D12 0.5%이며, 시즌6부터 생성하는 새 정책 전장은 D8 2.2%, D12 0.8%(D4/D6 유지)입니다. 새 정책의 D6 명단 소진 시 이름 없는 D6 부장, D8/D12 소진 시 D4가 충원됩니다. 군주는 충원하지 않습니다. 정원이 차면 멈추고 미수령 병력을 적립하지 않습니다.

| 영토 | 정원 | 중립 수비군 |
| --- | ---: | ---: |
| 일반 영토 48곳 | 12명 | D4 2명 |
| 요충지 27곳 | 14명 | D4 4명 |
| 대거점 15곳 | 16명 | D4 6명 |

- 영토마다 공격·병사를 동반한 이동 후 10분 대기합니다. 장수·군주만 이동할 때는 개인별 10분 이동 대기를 사용합니다. 출발지에는 최종 1명 이상 남겨야 합니다. 이동한 병력과 점령 영토의 기존 행동 대기도 지킵니다. 첫 시작 행동은 즉시 가능합니다.
- 공격 점수는 `max(1, floor(주사위 합 × 0.9))`, 수비는 주사위 합 그대로입니다. 동점은 수비 승리입니다.
- 승자 기본 피해는 최종 점수 차 0~2점 3명, 3~5점 2명, 6~9점 1명, 10점 이상 0명이며 최소 1명이 생존합니다. 낮은 등급부터 전사하며 보호 특기를 적용합니다. 패전 D6·D8·D12는 차이 0~2점 30%, 3~5점 15%로 생존 추첨 후 인접 내 영토로 퇴각할 수 있습니다. D20은 이 일반 생존에서 제외합니다.
- 점령지 정원을 넘으면 낮은 등급부터 출발지로 귀환하며 10분 대기합니다.
- 군주가 전사해도 영토가 남으면 계속합니다. 마지막 영토를 잃으면 1시간 후 새 출발할 수 있습니다. 게임 전체의 종료 조건은 없습니다.
- 승인 절차는 없습니다. 복귀 대기는 빈자리에 우선 배치되며 10분 행동 대기를 적용합니다. 대기 중 병력은 효과·전투에서 제외되지만 생존과 이름 예약에는 포함합니다.
- 시작 영토는 20분 보호되며 먼저 공격하면 자신의 시작 보호가 해제됩니다.
- 전사한 장수는 다시 등장할 수 있습니다. 살아 있는 역사 무장은 전장 전체에서 한 명입니다. 해당 등급의 이름이 모두 사용 중이면 D4가 대신 충원됩니다.
- 전체 채팅은 기본 최근 5개, 열면 최근 50개입니다. 서버에는 50개 슬롯만 저장하며 이전 메시지를 교체합니다. 메시지는 200자, 1초당 1개입니다.

## 저장 구조와 운영 범위

현재 시즌 1은 `worlds/season-1`에 공통 전황, `chat/season-1`에 전체 채팅을 저장합니다. 테스트 시즌 `worlds/main`과 `chat/global`은 읽기 전용으로 보존합니다. 변경된 경로만 한 번에 저장하며 전황 버전 검사를 통해 동시 쓰기를 감지합니다. 다른 영토의 명령과 충돌하면 최신 전황으로 최대 6회 재시도하고, 선택한 공격 영토 자체가 바뀌면 재선택하도록 알립니다. 같은 명령의 재전송은 중복 반영하지 않습니다. 전황과 중복 방지 기록은 각 100개입니다. 한 기기의 명령과 채팅은 순서대로 보내 SDK 내부 트랜잭션이 서로 취소되지 않게 합니다.

충원은 기준 시각과 고정 난수, 충원 예정 시각·영토 ID의 일정한 처리 순서로 계산합니다. 최소 한 접속자가 활동 중이면 필요한 때만 전체 영토의 충원을 묶어 정산하며, 모두 미접속이면 다음 접속에서 경과 시간을 반영합니다. 매초 서버에 쓰거나 상시 실행되는 충원 서버를 사용하지 않습니다. 새 장수 사건과 시스템 채팅은 전황 변경과 같은 다중 경로 갱신으로 모두 저장하거나 모두 재시도합니다. 이미 정산된 충원은 다시 쓰지 않습니다. 화면의 경과 시간은 Firebase 서버 시차를 적용합니다. 연결이 끊기면 공격과 채팅 전송을 막습니다.

기존 전황의 `version: 1`을 보존하고 `featureVersion: 4`, `rosterVersion: 2`, `effectsVersion: 1`, `rolePolicyVersion: 1`, 통계와 군주 생존 ID를 추가합니다. 새 화면은 이관 전 잠시 대기하며, 새 규칙 게시 후 구버전 화면의 쓰기를 차단해 통계와 명단 이관이 되돌아가지 않게 합니다. 업데이트 후 열려 있던 화면은 새로고침해야 합니다. 운영 전황 백업에는 참가자 기록이 들어 있으므로 저장소에 커밋하지 않습니다.

주사위 판정은 공격자의 기기에서 처리합니다. Firebase는 Google 로그인, 소유권, 명령 범위, 명령 시각, 전황 버전, 자료 형태 등을 검사합니다. **지인 간 신뢰를 전제로 하며 클라이언트 코드를 변조하는 참가자의 주사위 조작까지 막는 구조는 아닙니다.** Google 계정 여러 개를 사용하는 행위도 자동으로 막지 않습니다. 서버 권위 판정이나 참가자 초대 제한이 필요해지면 별도 개발합니다.

무료 한도 내 운영을 목표로 하며 유료 결제 계정을 연결하지 않았습니다. Spark 한도를 넘으면 서비스가 제한될 수 있습니다. 실제 10~15명 장기 플레이의 트래픽·게임 균형은 운영하면서 확인해야 합니다. 자동 검증에는 게임 규칙과 지도 연결 관계, Firebase 저장·권한·경합·채팅이 포함됩니다. 에뮬레이터 테스트는 실제 여러 사람의 기기·계정 접속 시험과 구분합니다.
