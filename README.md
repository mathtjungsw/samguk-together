# 삼국 · 함께 천하

지인 10~15명이 각자의 시간에 접속하는 주사위 영토 전략 게임입니다. 기존 `samguk-dice` 솔로 게임과 독립된 프로젝트입니다.

- 게임: https://mathtjungsw.github.io/samguk-together/
- Firebase: `samguk-together` · Spark 무료 요금제 · Realtime Database 싱가포르
- Google 계정으로 접속한 뒤 전장에 표시할 군주 이름을 정하고 지도에서 시작할 영토를 선택합니다. 같은 전황과 전체 채팅을 공유합니다. 이름은 1~16자이며 군령 아래의 ‘군주 이름 바꾸기’에서 다시 정할 수 있습니다.
- 기존에 Google 계정 이름으로 자동 등록된 군주는 처음 접속할 때 이름을 확인합니다. 이미 보유한 영토와 병력은 유지되며, 살아 있는 군주 병력에도 새 이름이 적용됩니다. 이전 전황·채팅 기록의 이름은 작성 당시 이름으로 남습니다.
- ‘이 기기에서 연습하기’는 별도 로컬 기록입니다. 온라인 전장으로 이전하지 않습니다.

## 2026-10-27 개선 업데이트

- PC에서 지도는 왼쪽 전체에, 군주 현황·영토 명령·랭킹·전황·전체 채팅은 오른쪽에 표시합니다. 휴대폰에서는 정보 패널을 접을 수 있습니다.
- 비단 지도와 군웅의 전술판을 탭으로 전환합니다. 선택한 영토·출전 병력·확대 위치를 유지하며, 같은 영토를 다시 누르면 선택이 해제됩니다. 공격 대상을 다시 누르면 대상만 해제합니다.
- ‘무장 100인’에서 전체 초상을 확인합니다. 유비·조조·손권을 포함해 D6 50명, D8 30명, D12 20명입니다. D20은 플레이어 본인입니다. 역사 인물 등급은 게임 편성을 위한 값입니다.
- 기존 소유 장수 중 새 명단에서 제외된 이름은 같은 D등급의 다른 장수로 자동 교체합니다. 병력 수·ID·등급·행동 대기·영토와 군주 이름은 보존하고, 교체를 새 충원으로 알리지 않습니다. 같은 군주의 미보유 이름을 우선하며 등급 명단을 모두 보유했으면 같은 등급에서 다시 모집합니다.
- 랭킹은 영토·병력·처치·전사를 기준으로 정렬합니다. 기본 순서는 영토 → 병력 → 처치이며 같은 값은 공동 순위입니다. 처치·전사는 **기존 전장의 새 버전 전환 시점부터** 누적하며 재참가 후에도 유지합니다. 중립 수비병 처치도 포함합니다.
- D6·D8·D12 충원과 D20 군주 부활은 접속자 전체 알림·전황·‘전령’ 시스템 채팅으로 공유합니다. 사용자 대화와 시스템 소식을 합쳐 서버에는 최신 50개 채팅만 남깁니다.
- D20이 전사했고 영토가 남아 있으면 내 영토에서 ‘군주 살리기’를 선택합니다. 그 영토에서 행동 가능한 D4·D6·D8·D12의 **면수 합계 20 이상**을 소모해 D20 1명과 교환합니다. 초과 비용은 반환하지 않습니다. 예: D12+D8, D8+D6+D6, D4 다섯 명. 교환한 병력은 전사 통계에 넣지 않습니다.
- 부활은 해당 영토의 행동 1회입니다. 영토와 부활한 군주는 10분을 기다리며 새 시작 보호는 생기지 않습니다. 살아 있는 자기 D20이 있거나, 마지막 영토를 잃었다면 부활할 수 없습니다.
- 적용한 업데이트의 전체 공지는 전황·전체 채팅에 한 번 기록합니다. 여러 사람이 동시에 접속해도 같은 공지를 중복 전송하지 않습니다. 처음 보는 기기에는 완료 알림도 표시합니다.

개발 범위와 검증 계획은 [DEVELOPMENT_PLAN.md](./DEVELOPMENT_PLAN.md), 최초 제안과 변경 결정은 [IMPROVEMENTS.md](./IMPROVEMENTS.md)에 있습니다.

## 실행과 배포

Node.js 24와 npm을 사용합니다.

```sh
npm ci
npm run dev
```

`http://localhost:4190`에서 엽니다. `npm run dev`는 시작할 때 한 번 빌드합니다. 수정 후 `npm run build`하고 새로고침하면 반영됩니다.

```sh
npm test
npm run test:rules
npm run build
```

보안 규칙 검증에는 Java 21 이상이 필요합니다. Windows의 공통 설치 경로는 `C:/Users/codex/.codex/skill-runtimes/firebase-java/jdk-21.0.9+10-jre`입니다. `JAVA_HOME`과 PATH를 지정하여 사용합니다. `test:rules`는 실제 전장 대신 `demo-samguk-online` 에뮬레이터만 사용합니다. 에뮬레이터가 이미 실행 중이라면 `node --test tests-rules/*.test.mjs`를 사용합니다.

`main`에 푸시하면 GitHub Actions가 규칙·저장·채팅 검증과 빌드를 수행한 다음 `dist/`를 GitHub Pages에 배포합니다. Firebase 규칙은 사이트 배포와 별개입니다. 변경 시 `node tools/generate-rules.mjs`로 생성하고 에뮬레이터 검증 후 Firebase Console에 게시하거나, Firebase CLI 로그인 후 `npx firebase deploy --only database --project samguk-together`로 반영합니다. 사이트 배포에 관리자 키나 서비스 계정은 필요하지 않습니다.

`firebase-config.json`은 브라우저용 공개 연결 정보입니다. 서버 관리자 비밀키를 넣지 않습니다. 데이터 접근 권한은 `firebase.database.rules.json`이 제한합니다. Google 로그인 허용 도메인은 `localhost`, `samguk-together.firebaseapp.com`, `samguk-together.web.app`, `mathtjungsw.github.io`입니다.

## 게임 규칙

- 역사 지명·위치를 참고한 90개 영토. 비단 지도와 성곽 표식으로 표시하며, 변을 공유하면 인접하고 최대 인접 5곳입니다. 장식과 경계 표현이 달라져도 연결 관계는 그대로입니다. 강·산 표시와 지형 보정은 없습니다.
- 처음 원하는 중립 영토에서 D20 군주 1명과 D4 병사 4명으로 시작합니다. 점령된 영토는 현재 주인에게 요청하여 승인받습니다.
- 병력은 D4 병사, D6 부장, D8 장수, D12 장군, D20 군주입니다. 군주는 플레이어 본인이며 100명의 무장은 소속 구분 없이 등장합니다. 초상은 이 게임을 위해 제작했습니다.
- 소유 영토마다 미접속 중에도 10분당 1명 충원합니다. 확률은 D4 80%, D6 15%, D8 4%, D12 1%. 군주는 충원하지 않습니다. 정원이 차면 멈추고 미수령 병력을 적립하지 않습니다.

| 영토 | 정원 | 중립 수비군 |
| --- | ---: | ---: |
| 일반 영토 48곳 | 12명 | D4 2명 |
| 요충지 27곳 | 16명 | D4 4명 |
| 대거점 15곳 | 20명 | D4 6명 |

- 영토마다 공격·이동 후 10분 대기합니다. 출발지에는 1명 이상 남겨야 합니다. 이동한 병력과 점령 영토도 10분 기다립니다. 첫 시작 행동은 즉시 가능합니다.
- 공격 점수는 `max(1, floor(주사위 합 × 0.9))`, 수비는 주사위 합 그대로입니다. 동점은 수비 승리입니다.
- 패자는 참전 병력이 전멸합니다. 승리한 공격자는 적 인원 40%, 수비자는 적 인원 20%를 올림한 만큼 잃으며 최소 1명 생존합니다. 낮은 등급부터 전사합니다.
- 점령지 정원을 넘으면 낮은 등급부터 출발지로 귀환하며 10분 대기합니다.
- 군주가 전사해도 영토가 남으면 계속합니다. 마지막 영토를 잃으면 1시간 후 새 출발할 수 있습니다. 게임 전체의 종료 조건은 없습니다.
- 영토 양도는 현재 주인만 승인할 수 있습니다. 기존 병력은 주인의 다른 영토로 돌아갑니다. 공간이 부족하거나 마지막 영토라면 승인할 수 없습니다. 새 참가자는 5명으로 시작합니다.
- 시작 영토는 20분 보호되며 먼저 공격하면 자신의 시작 보호가 해제됩니다.
- 전사한 장수는 다시 등장할 수 있습니다. 살아 있는 장수의 이름은 같은 플레이어 내에서 가급적 중복하지 않습니다.
- 전체 채팅은 기본 최근 5개, 열면 최근 50개입니다. 서버에는 50개 슬롯만 저장하며 이전 메시지를 교체합니다. 메시지는 200자, 1초당 1개입니다.

## 저장 구조와 운영 범위

`worlds/main`에 공통 전황, `chat/global`에 전체 채팅을 저장합니다. 변경된 경로만 한 번에 저장하며 전황 버전 검사를 통해 동시 쓰기를 감지합니다. 다른 영토의 명령과 충돌하면 최신 전황으로 최대 6회 재시도하고, 선택한 공격 영토 자체가 바뀌면 재선택하도록 알립니다. 같은 명령의 재전송은 중복 반영하지 않습니다. 전황과 중복 방지 기록은 각 100개입니다. 한 기기의 명령과 채팅은 순서대로 보내 SDK 내부 트랜잭션이 서로 취소되지 않게 합니다.

충원은 기준 시각과 고정 난수, 충원 예정 시각·영토 ID의 일정한 처리 순서로 계산합니다. 최소 한 접속자가 활동 중이면 필요한 때만 전체 영토의 충원을 묶어 정산하며, 모두 미접속이면 다음 접속에서 경과 시간을 반영합니다. 매초 서버에 쓰거나 상시 실행되는 충원 서버를 사용하지 않습니다. 새 장수 사건과 시스템 채팅은 전황 변경과 같은 다중 경로 갱신으로 모두 저장하거나 모두 재시도합니다. 이미 정산된 충원은 다시 쓰지 않습니다. 화면의 경과 시간은 Firebase 서버 시차를 적용합니다. 연결이 끊기면 공격과 채팅 전송을 막습니다.

기존 전황의 `version: 1`을 보존하고 `featureVersion: 2`, `rosterVersion: 1`, 통계와 군주 생존 ID를 추가합니다. 전환 전에는 기존 화면의 명령을 허용하고, 새 전황으로 전환한 후에는 구버전 화면의 쓰기를 차단해 통계와 명단 이관이 되돌아가지 않게 합니다. 업데이트 후 열려 있던 화면은 새로고침해야 합니다. 운영 전황 백업에는 참가자 기록이 들어 있으므로 저장소에 커밋하지 않습니다.

주사위 판정은 공격자의 기기에서 처리합니다. Firebase는 Google 로그인, 소유권, 승인자, 명령 시각, 전황 버전, 자료 형태 등을 검사합니다. **지인 간 신뢰를 전제로 하며 클라이언트 코드를 변조하는 참가자의 주사위 조작까지 막는 구조는 아닙니다.** Google 계정 여러 개를 사용하는 행위도 자동으로 막지 않습니다. 서버 권위 판정이나 참가자 초대 제한이 필요해지면 별도 개발합니다.

무료 한도 내 운영을 목표로 하며 유료 결제 계정을 연결하지 않았습니다. Spark 한도를 넘으면 서비스가 제한될 수 있습니다. 실제 10~15명 장기 플레이의 트래픽·게임 균형은 운영하면서 확인해야 합니다. 자동 검증에는 게임 규칙과 지도 연결 관계, Firebase 저장·권한·경합·채팅이 포함됩니다. 에뮬레이터 테스트는 실제 여러 사람의 기기·계정 접속 시험과 구분합니다.
