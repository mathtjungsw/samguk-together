# 강화 통신 절감 · 2026-11-03

사용자의 직접 개선 요청에 따라 구현·검증·서버/사이트 배포·현재 시즌5 활성화·전체 공지를 완료했다. 강화 성공 추첨을 PC로 옮기지 않고, 실제 반복 전송과 조회를 줄인다.

## 변경

- 최근100개 강화 결과를 전장 재시도 기록과 전황에 중복 저장하던 형식을 줄인다. 전장에는 ID/군주/순번/시각/상세 버전과 전황 텍스트를 남기고 전체 결과는 enhancementRecords/시즌/요청/버전에 보존한다. 재시도 보존 건수는100개 그대로다.
- 원본 상세는 전장과 같은 트랜잭션의 enhancementOutbox에 먼저 확정한다. 불변 상세 저장+대기 제거를 원자 업데이트한다. 전달 실패 시 원본이 남고 같은 요청 재확인·후속 명령·AI에서 다시 전달한다. 전황이나 재시도 기록이 참조하는 동안 상세를 삭제하지 않는다. 원래100개 보관에서 벗어나 어느 곳에서도 참조하지 않는 버전만 정리한다.
- 기존 저장은 별도 활성화 전까지 원래 형식이다. 호환 서버/규칙/사이트 배포 후 활성화 도구가 현재 전장을 백업하고 ETag로 보호하며 기록 형식만 이관한다. 설정은 서버 전용 serverOptimizations/enhancementRecords 경로이고 함수에서60초 캐시한다. 다음 시즌도 첫 강화 확정과 함께 이관된다.
- 강화 응답 성공 시 결과를 즉시 화면에 전달한다. 최신 enhanceSeq를 이미 실시간으로 받았다면 추가 조회가 없다. 늦으면500ms 후 전황만 확인하고2/5초 간격으로 최대2회 추가 확인한다. 채팅은 다시 읽지 않는다. 최신 병력이 확인되기 전에는 다음 행동을 잠그고 계정·시즌별 확정 상태를 기기에 보존한다.
- 응답 유실 시 같은 요청ID/순번으로만 재확인한다. 저장된 결과를 재사용하며 다시 추첨하거나 재료를 추가 소모하지 않는다. 후속 조회 실패는 성공한 요청을 미확인 추첨으로 바꾸지 않는다.
- 재료 선택·확률 미리보기는 기존 로컬 처리다. 최종 난수·최신 상태 검증·재료 소모·단계/실패/사망·색인은 서버에서 함께 확정한다. 성공률·비용·대기·전투 잠금·부활/포로/시즌/AI 규칙은 유지한다. 서버는 여전히 전체 전장 트랜잭션을 사용한다.

## 비교 계측

격리 demo-enhancement-traffic DB 에뮬레이터에서 같은 전장·기존 강화100건·같은 강화1회·같은 난수·10명의 실시간 구독자로 비교했다. 실제 faye WebSocket message의 UTF-8 수신 payload를 계측했으며 TLS/HTTP 오버헤드나 실제 청구는 포함하지 않는다.

| 항목 | 기존 | 개선 |
|---|---:|---:|
| 초기 활성 전장 JSON | 183,068 bytes | 143,082 bytes |
| 강화 후 활성 전장 JSON | 179,992 bytes | 142,930 bytes |
| 강화1회 수신 WebSocket payload | 1,529,851 bytes | 1,452,660 bytes |

이 합성 조건의 수신량 약5.05% 감소, 초기 활성 JSON 약21.84% 감소다. 실제 병력 결과 일치도 검사했다. 동일 데이터 크기 감소가 동일한 청구/응답시간 감소를 의미하지 않는다. 실제 전송은 기록 분포·동시 접속·명령 횟수에 따라 달라진다. 현재 SDK도 변경분 동기화를 수행하므로 단순 JSON 크기만으로 비용 절감률을 계산하지 않았다. 강화 후 불필요한 채팅 재조회 생략 효과는 별도이며 위 수신 비교에 추가 합산하지 않았다.

원본 계측: playtest/enhancement-traffic-proof.json. 도구: tools/benchmark-enhancement-traffic.mjs. 운영에서 시험 강화·공격·이동·보상 사용은 하지 않는다. 실제 휴대전화 응답시간 전후 비교는 수행하지 못했다.
