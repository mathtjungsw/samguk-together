# 삼국 · 함께 천하 — 다음 개선 상세 개발계획

작성일: 2026-10-27 · 대상: `samguk-online` · 예상 참가자: 10~15명

최신 반영: 중립 영토가 없으면 영토 수 1위의 영토를 승인 없이 무작위 재배정한다. 기존 승인 양도안은 폐기했으며, 공동 1위·기존 병력 복귀·공간 부족·관련 간옹 효과와 검증 계획도 함께 갱신했다.

**2026-10-27 사용자의 ‘게임 구현 배포 해줘’ 요청으로 구현을 진행했다.** 이 문서의 추천 세부안을 포함해 구현했으며 자동 검증과 운영 배포를 완료했다. 사용자 요구와 이번 계획의 추천 세부안을 아래에서 구분한다. 구현 단계에서 규칙을 임의로 크게 바꾸지 않는다.

- 요구사항 원장: [IMPROVEMENTS.md](./IMPROVEMENTS.md)
- 무장 100명의 효과·역사 근거: [HERO_EFFECTS_PROPOSAL.md](./docs/HERO_EFFECTS_PROPOSAL.md)
- 이전 적용 완료 개발계획: [보관본](./docs/archive/DEVELOPMENT_PLAN_2026-10-27_COMPLETED.md)
- JPG 11장은 최초 효과 제안의 이미지 사본이다. 이후 확률·운영 규칙은 이 상세 계획을 우선하며, 이미지가 현재 운영 규칙이라고 안내하지 않는다.

추천 세부안은 이번 문서에서 검토할 구체적인 기본값이지 이미 운영 중인 규칙이 아니다. 이 계획에 따라 업데이트를 요청하면 해당 기본값을 구현 기준으로 삼되, 실제 저장의 사전 조사에서 새로운 손실 위험이 발견되면 해당 이관만 재검토한다.

### 그대로 유지할 게임 기반

- 90개 영토와 현재 인접 관계, 인접 최대 5곳, 강·산 및 지형 보정 없음.
- D4·D6·D8·D12·D20의 다섯 병력 등급. D20은 플레이어 본인.
- 기본 충원·행동 대기 10분. 고유 효과로 명시한 경우만 예외 적용.
- 공격 기본 점수 `max(1, floor(주사위 합 × 0.9))`, 수비는 합계 그대로, 동점 수비 승리.
- 승리 공격군 손실은 적 인원 40%, 승리 수비군 손실은 적 인원 20% 올림. 최소 한 명 생존. 특기가 실제 보호한 인원만 손실에서 제외.
- 공격 인원 상한을 추가하지 않으며 공격 출발지 최소 1명 잔류 유지.
- 마지막 영토를 잃으면 1시간 후 재시작, 영토가 남으면 군주 전사 후에도 계속 플레이. 전체 전장 종료 조건 없음.
- 전체 채팅 미리보기 5개·확장 50개·서버 최신 50개, 전황 최신 100개.
- 기존 Google 로그인·Firebase RTDB·GitHub Pages와 원본 생성 초상 사용. 새 유료 서비스·추가 이미지 제작은 이번 범위에 없음.

## 2. 소스와 기존 저장에서 확인한 출발점

| 확인한 사항 | 필요한 변경 |
| --- | --- |
| `recruitedUnit()`은 해당 군주의 생존 이름만 제외하고, 후보가 없으면 같은 등급의 이름을 다시 뽑음 | 전장 전체 생존 이름 제외와 D4 대체로 변경 |
| `unitTier()`는 80 / 15 / 4 / 1% | 확률을 한 설정에서 공유하고 충원·효과 설명·검증에 함께 사용 |
| `settleRecruitment()`는 전 영토의 충원을 시간·영토 ID 순으로 정산 | 이 순서를 유지하고, 가변 충원 간격·이름 예약·보너스 충원을 하나의 사건 순서로 통합 |
| `normalizeWorld()`와 Firebase 규칙은 영토별 기본 정원 및 최대 20개 병력 칸을 전제 | 정원 효과와 정원 감소 후 초과 주둔을 지원. 저장 가능한 물리 상한은 기본 정원 +3 |
| Firebase 병력 대기 검사는 대체로 10분 상한, 수동 정산은 고정 10분 배수를 검사 | 탈출 20분·가변 충원·준비 시각을 허용하되 검증을 무제한 완화하지 않음 |
| `validateMove()`는 목적지 정원 초과와 출발지 전원 이동을 먼저 거부 | 일반 이동·상호 교환·공격을 구분해 최종 상태를 검사 |
| `winProbability()`는 특기 없는 원래 주사위 승률 계산 | 특기 적용 예상 승률을 따로 계산하고 근삿값임을 표시 |
| 현재 시작은 영토를 직접 고르고 점령지에는 신청·승인·거절 명령을 사용 | 중립/영토 수 1위 자동 배정으로 통합하고 새 버전의 신청·승인·거절 절차 제거 |
| ‘무장 100인’은 정적인 초상·등급 갤러리 | 현재 전황과 연결한 보유자·위치·상태·효과 조회 및 내 장수 이동 화면으로 확장 |
| 현재 저장은 `featureVersion:2`, `rosterVersion:1`, 명령 `protocol:2` | 새 기능의 저장·규칙·구버전 차단을 함께 전환 |

기존 배포 직후 로컬 백업 한 건에서는 역사 무장 99명(D6 74명 / D8 21명 / D12 4명), 중복 이름 30종·추가 중복 개체 37명, 명단 표준보다 실제 등급이 높은 병력 6명을 확인했다. **과거 백업의 집계이며 현재 운영 수치가 아니다.** 참가자 이름·계정·개별 배치를 이 계획에 복사하지 않는다. 실제 업데이트 직전에 새 백업으로 다시 조사한다.

## 3. 시작 영토 무작위 배치

### 정상 시작 흐름

1. Google 로그인 → 군주 이름 설정 → **‘무작위 영토에서 시작’** 버튼.
2. 현재 소유자가 없는 중립 영토를 모두 후보로 삼는다. 일반·요충지·대거점은 현재 지도 분포 그대로 포함하고 후보 영토별 균등 기회를 준다. 시작 병력은 기존처럼 D20 1명 + D4 4명이다.
3. 엔진이 후보를 선택한다. 참가자가 명령에 임의의 영토 ID나 추첨 씨앗을 넣어 결과를 지정하지 못하게 한다.
4. 배치 확정 후 해당 영토로 지도 중심을 이동하고 안내한다. 기존 20분 시작 보호와 첫 행동 즉시 가능 규칙을 유지한다.
5. 재참가도 같은 방식이며, 마지막 영토 상실 후 1시간 대기를 통과해야 한다. 중립 영토가 없으면 아래의 1위 영토 재배정을 같은 시작 명령 안에서 처리한다.

### 재추첨과 동시 참가

- 추첨 키는 전장 씨앗·참가자 ID·다음 생애 번호로 고정한다. 각 후보에 고정 순위를 부여하고 현재 가능한 첫 후보를 택한다. 시간·명령 ID·새로고침으로 임의 재추첨하지 않는다.
- 명령 결과를 보기 전에 임의 영토가 이미 점유되면 최신 전황에서 남은 후보로 다시 결정한다. 전장 버전 검사로 같은 땅에 두 명이 시작하지 못하게 한다.
- 다른 사람의 정상 참가나 점령으로 후보 집합이 달라지면 결과도 바뀔 수 있다. 이를 고정 예약이나 특정 위치 보장으로 표시하지 않는다.

### 중립 영토가 하나도 없을 때 — 사용자 확정 규칙

1. 해당 시점까지 충원을 정산한 최신 전황에서 참가자별 **현재 소유 영토 수**를 계산한다. 병력 수·처치 수·전체 랭킹의 보조 정렬을 사용하지 않는다.
2. 영토 수 1위가 여러 명이면 공동 1위 중 한 명을 균등 무작위로 고른다. 그 군주의 모든 영토 중 한 곳을 다시 균등 무작위로 고른다. 공동 1위 추첨과 영토 추첨의 난수 키를 구분한다.
3. 선정된 영토는 시작하는 참가자의 소유로 바꾸고 D20 1명 + D4 4명으로 시작시킨다. 기존의 시작 보호 20분·첫 행동 즉시 가능·재참가 1시간 대기는 유지한다.
4. **기존 소유자의 승인·거절은 받지 않는다.** 해당 영토에 장수가 있거나 병력이 많다는 이유로 다른 후보로 다시 뽑지 않는다. 참가자도 원하는 영토를 직접 지정할 수 없다.
5. 주둔 중인 원주인의 병력은 아래 복귀 처리로 보존한다. 전투를 치르지 않으므로 전투 승패·처치·전사·점령 전공을 발생시키지 않는다. 원주인의 영토 수만 1곳 줄고, 순위는 새 상태에서 다시 계산한다.

공동 1위 추첨은 이번 상세 계획의 추천 세부안이며, ‘영토 수 1위에서 승인 없이 무작위 시작’은 사용자 결정이다. 이 규칙은 새 시작에만 적용하며 기존 참가자의 영토를 일괄 재배치하지 않는다.

### 기존 주둔 병력 복귀 — 추천 세부안

- 선정 영토를 비우기 전에 원주인의 다른 영토를 대상으로 복귀 계획을 계산한다. 가까운 영토부터, 거리 동률은 영토 ID 순으로 정한다. 이 복귀는 일반 이동의 인접 조건을 따르지 않는 시스템 회수다.
- 원래 병력 ID·이름·실제 D등급·효과의 생애 상태·소유자를 유지한다. 병력을 새 참가자에게 넘기거나 D4로 바꾸지 않는다. D20이 있었다면 원주인의 군주도 같이 복귀한다.
- 가능한 빈자리에는 무장·군주 우선, 같은 범주에서는 높은 D등급·병력 ID 순으로 배치한다. 역사 무장의 현재 위치 색인을 같은 저장에서 바꾼다.
- 복귀한 병력의 행동 대기는 `max(기존 행동 가능 시각, 복귀 시각+10분)`이다. 이미 적용된 20분 탈출 대기 등을 줄이지 않는다. 새 시작 영토의 기존 담당·수비 특기·지원 관계는 해제한다.
- 원주인 영토의 자리가 부족한 병력은 **원주인 소유의 ‘복귀 대기’ 목록**에 보관하는 안을 추천한다. 공간 부족 때문에 신규 참가를 승인 대기로 되돌리거나 기존 병력을 삭제하지 않는다.
- 복귀 대기 병력은 지도 위 주둔 병력 수·전투 인원·내정/수비/기동 담당·군주 부활 재료에서 제외한다. 보너스 충원이나 고유 효과도 발동하지 않는다. 새 병력을 생산하는 예비 부대 시스템은 아니다.
- 복귀 대기 병력도 살아 있는 개체다. 역사 무장 이름을 계속 예약하고, D20이 있으면 군주는 생존으로 판단해 중복 부활을 막는다. 내 장수 목록의 현재 위치에는 **‘복귀 대기’**를 표시하고, 합계 병력은 `주둔 N명 · 복귀 대기 M명`으로 구분한다.
- 원주인의 영토에 실제 빈자리가 생기면 다음 명령/공유 정산에서 정규 충원보다 먼저 자동 배치한다. 최초 회수 때의 병력 우선순위와 고정 영토 순서를 사용한다. 재배치된 시점부터 다시 기본 10분 대기를 적용하고 이전의 더 긴 대기는 보존한다.
- 복귀 대기는 이 자동 시작 재배정으로 회수된 병력만 들어갈 수 있다. 정상 공격의 패잔병·포화 일반 이동·포화 교환·플레이어 임의 보관에는 사용하지 않는다.
- 대기 병력은 원주인의 현재 생애에 속한다. 이후 원주인이 전투로 마지막 영토를 잃으면 대기 병력도 해당 군세와 함께 해산하고 이름 예약을 해제한다. 이는 추가 전투 처치/전사가 아니며 다음 생애로 병력을 이월하지 않는다. 이 처리는 복귀 대기 도입에 따른 추천 운영 규칙으로 명시한다.

### 명령·동시 참가·전환

- 한 번의 시작 명령이 기존 병력 복귀/대기 → 새 소유권과 시작 병력 → 무장 위치 → 두 군주의 상태 → 시작 전황을 모두 반영한다. 일부만 성공할 수 없다.
- 실제 확정 직전에 중립 존재 여부와 영토 수 1위를 다시 계산한다. 여러 명이 동시에 시작하면 먼저 성공한 뒤의 순위를 기준으로 다음 명령을 재계산한다. 예전에 본 1위나 이전에 선택된 목적지를 고정 사용하지 않는다.
- 추첨 키는 생애 단위로 유지하되 후보 집합은 최신 상태를 따른다. 재시도 자체로 새 난수를 뽑지 않는다. 동일 명령 재전송으로 영토를 두 곳 받거나 기존 병력을 두 번 복귀시키지 않는다.
- 지도·명령창의 시작 영토 선택, 승인 요청·승인·거절 버튼을 제거한다. 새 버전에서 기존 `request`·`approve`·`reject` 명령을 거부하고, 전환 때 남은 신청은 취소 상태로 마감한다. 이미 끝난 과거 승인 기록은 역사 기록으로 보존한다.
- 이론적으로 90명이 모두 한 영토씩 소유하면 1위도 1곳뿐이다. 권장 참가 규모 10~15명을 벗어나는 이 상태에서는 마지막 영토를 강제로 빼앗아 기존 참가자를 탈락시키지 않고 시작 대기로 처리하는 정원 예외를 둔다. 정상 범위의 1위가 2곳 이상이면 빈자리 부족을 이유로 배정을 막지 않는다.
- 원주인에게는 어떤 영토가 새 참가자에게 배정됐고 기존 병력 중 몇 명이 복귀/대기 중인지 알린다. 전황에는 기존 시작 사건에 원주인·재배정 영토·복귀 수를 부기하고 시스템 회수를 장수의 일반 이동 기록으로 중복 생성하지 않는다.

## 4. 전장 전체 무장 1명과 충원 확률

### 기본 추첨표 — 추천값

| 실제 결과 등급 | 확률 | 역사 무장 명단 |
| --- | ---: | ---: |
| D4 | 90% | 제한 없음 |
| D6 / B | 7% | 50명 |
| D8 / A | 2.5% | 30명 |
| D12 / S | 0.5% | 20명 |
| D20 | 0% | 군주는 정규 충원에서 제외 |

- 먼저 등급을 추첨한다. 해당 등급의 표준 이름 중 전장 전체에서 살아 있지 않은 후보를 균등 추첨한다.
- 후보가 없으면 그 충원 1건을 D4 1명으로 바꾼다. 다른 등급을 재추첨하지 않는다. D6만 소진되었다면 실제 분포는 D4 97% / D8 2.5% / D12 0.5%다.
- 이동·교환 이동·퇴각·행동 대기는 생존 상태다. 이름 예약을 해제하지 않는다.
- 실제 전사 또는 군주 부활 재료로 소모되어 개체가 없어지면 이름을 해제한다. 부활 재료 소모는 ‘전사’ 통계에 넣지 않지만 이름은 다시 뽑힐 수 있다.
- 소유자가 바뀌거나 시작 영토 재배정으로 복귀/복귀 대기해도 같은 개체가 유지되면 새 등장이 아니다. 무장 유일성 색인은 주둔 병력과 복귀 대기를 함께 확인한다. 새로 충원된 같은 이름은 별도 생애의 개체이며 특기 횟수·성장을 새로 시작한다.
- 정규 충원으로 새 ‘이름 없는 D6·D8·D12’를 만들지 않는다. 이름 없는 동급 병력은 기존 저장 보존용으로만 허용한다.

### 정산의 일관성

- 순서는 충원 예정 시각 → 영토 ID → 사건 종류의 고정 순서로 잡는다. 정규 충원 직후 해당 사건의 보너스 D4를 처리한다.
- 첫 정산자가 후보를 임시로 차지하는 것이 아니라, 같은 전황에 대해 화면 계산과 실제 저장이 같은 이름을 예측하도록 한다. 알림·확정 보유 위치는 저장된 전황을 기준으로 표시한다.
- 늦게 접속한 사람의 과거 충원도 같은 시간 순서로 처리한다. 새 전투 명령 전에 해당 시점까지의 충원을 먼저 정산한다.
- 전장 버전과 명령 중복 방지를 유지한다. 동일 이름을 동시에 뽑는 상황은 한 저장만 성공하고 다른 명령은 최신 후보로 재계산한다.

## 5. 기존 보유 장수 이관 — 병력 등급 보존

**사용자가 ‘등급 유지, 초과분은 이름 없는 동급 병력, 고유 효과 없음’을 선택했다.** 병력 초기화나 D4 강등을 하지 않는다.

### 처리 순서

1. 업데이트 직전 전체 전황·채팅·보안 규칙을 별도 백업한다. 신규 백업으로 중복·등급 차이·병력 총수·ID·대기·정원·소유권을 조사한다.
2. 역사 무장 이름마다 대표 1명을 남긴다. 같은 이름에 표준 등급과 맞는 개체가 있으면 그 집합을 우선하고, 그 안에서는 전장 씨앗과 개체 ID의 고정 추첨으로 대표를 정한다. 특정 계정이나 배열 순서에 우선권을 주지 않는다. 결정 결과는 재실행해도 같다.
3. 남은 중복 개체는 **실제 D등급과 같은 등급의 비어 있는 무장 이름**으로 교체한다. 이미 유지하기로 한 모든 이름을 먼저 예약한 뒤 배정해 나중에 중복이 생기지 않게 한다.
4. 동급 이름이 부족하면 D6 ‘이름 없는 부장’, D8 ‘이름 없는 장수’, D12 ‘이름 없는 장군’으로 바꾼다. 원래 ID·실제 면수·현재 위치·행동 가능 시각은 보존하고 고유 효과는 부여하지 않는다.
5. 이름 없는 기존 병력은 100명 역사 무장의 유일성 명단에서 제외한다. 전투 주사위·이동·교환 이동·군주 부활 재료에는 실제 D등급 그대로 참여한다. 새 충원으로 늘리지 않는다.
6. 대표로 남긴 이름의 실제 등급이 명단 표준보다 높다면 원래 면수를 보존한다. 효과는 이름의 표준 티어 효과를 그대로 사용하고 더 강한 효과로 승격하지 않는다. 개인 주사위 보정은 실제 면수를 넘지 않는다. 예: 기존 D12 서서는 D12 주사위와 서서의 B 특기를 가진다.
7. 반대로 표준보다 낮은 등급의 대표가 새 백업에서 발견되면, 낮은 병력에 상위 효과를 무조건 붙이지 않는다. 해당 개체는 이관 사전 검사에서 분리해 처리안을 다시 정한다. 확인한 이전 백업에는 이 반대 사례가 없었다.
8. 새 효과의 생애 횟수·승리 성장·점령 목록은 적용 시점부터 0으로 시작한다. 과거 전투를 추측해서 횟수를 차감하거나 성장시키지 않는다.
9. 유일성 색인을 만들고 전후 병력 수·ID·면수·소유권·대기 및 통계 보존을 기계적으로 대조한다. 두 번 실행해도 추가 이름 변경이나 병력 생성이 없어야 한다.

새 이름 배정과 이름 없는 병력 전환은 최초 등장 알림을 만들지 않는다. 전체 업데이트 안내와 내 장수 화면의 개별 변경 요약으로 설명한다. 운영 백업·계정별 변경표는 공개 저장소에 커밋하지 않는다.

## 6. 무장 100인 효과 구현 사양

### 범위와 사양 우선순위

- [효과 초안의 1~100번 표](./docs/HERO_EFFECTS_PROPOSAL.md)에 있는 **100명 모두**를 구현 범위로 한다. 초상·이름·표준 등급도 현재 명단을 재사용한다.
- 아래의 공통 계산 및 보완표가 초기 초안보다 우선한다. 수정하지 않은 개별 효과의 조건·수치는 100명 표를 따른다. 표와 코드 양쪽에 다른 수치를 따로 적지 않는다.
- 설명 문구와 실제 실행이 같은 효과 데이터에서 나오도록 만든다. 장수마다 독립적인 임의 코드를 100개 붙이기보다 공통 효과 유형과 조건·수치로 묶는다.
- 티어는 효과 예산이다. 역사적 위상의 우열로 안내하지 않으며 소설·주석의 일화 출처도 유지한다.

### 담당과 선택

| 기능 | 선택 방식 | 발동 조건 |
| --- | --- | --- |
| 내정 | 영토마다 담당 1명 | 해당 영토에 실제 주둔, 행동 가능, 효과에 맞는 역할 |
| 전투 | 공격 시 주장·보좌 최대 2명 / 수비는 사전 지정 최대 2명 | 실제 참전하고 행동 가능한 무장. 나머지 병력도 기본 주사위는 굴림 |
| 기동 | 이동 명령마다 담당 1명 | 출발 병력 중 실제 해당 특기를 가진 무장 |
| 인접 지원 | 내정 담당이 인접한 내 영토 1곳 지정 | 출발·지원 대상 모두 소유 조건 유지 |
| 퇴각 | 수비 영토마다 다른 내 영토 1곳 지정 | 패전 처리 때도 내 영토이고 빈자리 있음 |

- 내정·수비 지정은 즉시 유효하되 해당 자리의 다음 변경까지 10분을 둔다. 같은 대상 재선택으로 시계를 초기화하지 않는다. 담당 이동·전사는 지정을 비활성화하되 남은 변경 대기는 보존한다.
- 처음 고유 효과를 도입할 때는 빈 담당 자리만 추천 무장으로 자동 채운다. 내정은 적용 가능한 가장 높은 표준 티어, 수비는 해당 전투에 유효한 특기를 가진 무장을 우선하고 동률은 고정 ID로 정한다. 사용자가 선택한 기존 값은 자동으로 덮어쓰지 않는다.
- 병력의 행동 대기 중에도 수비 기본 주사위는 굴리지만 고유 효과는 발동하지 않는 안을 기준으로 한다. 탈출 후 20분이 연속 무적 시간이 되지 않는다.
- 내정 담당도 출전할 수 있다. 그 개체가 떠나면 정원·충원 지원이 끊기는 결과를 명령 전에 안내한다.
- 전체 무장 100인에는 고유 효과가 없는 이름 없는 병력과 D20을 역사 무장으로 끼워 넣지 않는다. ‘내 장수’ 목록에서는 이 병력들도 별도 구분해 관리할 수 있게 한다.

### 전투 계산 순서

1. 전투 직전 충원을 정산하고 참전 병력·원래 눈·특기 2명·전적·인원 조건을 고정한다.
2. 능력 난수는 전투 사건·무장 ID·효과 ID로 분리한다. 주사위 재굴림이 원래 전투 주사위의 순서를 바꾸지 않게 한다.
3. 낮은 눈 재굴림 → 아군 개인 눈 증가/최저 눈 → 상대 눈 감소 → 공격 계수 → 최종 가산/감점 순으로 계산한다. 같은 단계의 두 효과는 고정 효과 ID 순서로 처리한다. 동률 대상은 원래 눈과 병력 ID로 결정한다.
4. 같은 주사위는 한 번만 재굴린다. 제갈량과 순유가 함께 있으면 제갈량을 먼저 처리하고 순유는 남은 대상에 적용한다. 진무의 발동 여부는 보정 전 본인 눈이 6이었는지로 판정한다.
5. 사마의·진궁·가후는 상대의 최종 가산만, 동윤은 받는 최종 감점만 지운다. 다른 효과를 지워 자기 효과가 다시 커지는 순환 계산은 하지 않는다.
6. 원래 주사위 기반 점수와 비교한 아군 점수 이익은 특기당 최대 +8, 진영 합계 최대 +10으로 제한한다. 상대가 유발하는 점수 감소는 합계 최대 6이다. 증가·감소를 분리 기록해 상쇄로 상한을 우회하지 못한다. 황개의 본인 눈 -1 비용은 적 감소와 별도로 지불한다.
7. 모든 주사위는 1~실제 면수, 최종 점수 최소 1. 공격만 내림하며 동점 수비 승리를 유지한다.
8. 승패 → 기본 사상자 → 승자 D4 보호 → 패자 호위·탈출 → 점령 병력 배치·초과 귀환 → 점령 보너스 → 실제 전사·처치 통계 → 살아 있는 이름 색인 순으로 처리한다.
9. 한 특기의 승패 조건에 자기 처리로 바뀐 결과를 다시 넣지 않는다. 승패가 정해진 뒤 생존 특기가 영토 점령을 취소하지 않는다.

특기로 이긴 경우도 기존 인원 기반 손실 공식을 따른다. 승리 군의 고등급 무장이 기본 사상자로 선정되었다고 해서 ‘패전 탈출’ 특기를 발동하지 않는다.

### 준비·충원·정원

- 정규 충원 예정 시각을 저장한다. 담당이 바뀌어도 진행 중인 주기를 보존하고 **다음 주기부터** 새 간격을 적용한다. 영향이 끊길 때도 이미 시작한 한 주기를 매번 다시 시작하지 않는다.
- 정원이 차면 충원 시계와 정규 충원 횟수를 적립하지 않는다. 실제 빈자리가 생긴 행동 시각부터 해당 간격으로 다시 시작한다. 동수 교환으로 빈자리가 생기지 않으면 충원 시계도 새로 적립하지 않는다.
- 보너스는 D4 1명이며 정원이 허용할 때만 지급한다. 보너스가 다른 보너스를 만들거나 정규 충원 횟수를 올리지 않는다.
- 내정 준비·연속 평화·생애 횟수는 서로 다른 상태로 관리한다. 이동·담당 해제는 연속 준비를 끊지만 생애 누적 충원·승리·사용 횟수·12/24시간 재사용 대기는 초기화하지 않는다.
- 주둔 정원 보너스는 최대 +3. 담당이 떠나 정원이 내려가도 초과 병력을 삭제하지 않는다. 초과 상태는 충원·순증 이동을 막고 감원 이동 및 병력 수가 늘지 않는 장수 교환은 허용한다.
- 중립 영토는 특기 충원하지 않는다. 점령 순간부터 새 소유자의 담당 지정과 준비 규칙을 적용한다.

### 생존·호위

- 조운은 패전 전사 위기에서 생애 최대 2회 확정 탈출, 주태는 1회, 맹획은 50% 탈출 판정에 성공한 횟수 최대 2회다. 맹획의 실패는 정상 전사이며 재접속으로 다시 뽑지 않는다.
- 전위·조홍·관평은 정해진 대상 1명을 구하고 자신은 전사한다. 대상은 전투 전에 지정하고 조건 불충족·퇴각 공간 없음이면 발동하지 않는다.
- 공격 패전의 퇴각은 내 출발지, 수비 패전은 미리 고른 다른 내 영토다. 수비 목적지가 유효하지 않으면 남은 내 영토 중 인접 우선·영토 ID 순으로 빈자리 1곳을 찾는 추천 자동 대안을 둔다. 퇴각은 전투 후 회수 예외이며 일반 이동·공격 연결을 추가하지 않는다.
- 퇴각은 D4 교환을 강제로 발생시키지 않는다. 빈자리가 없거나 마지막 영토를 잃으면 정상 전사한다. 여러 명의 퇴각은 같은 처리 안에서 호위 대상 우선 → 자기 생존 → 병력 ID 순으로 공간을 예약한다.
- 살아남은 개체는 20분 행동 대기, 실제 성공한 생존 횟수만 차감한다. 대리 희생자를 다른 생존 특기로 되살리지 않는다. 부활 재료 소모에는 생존·호위를 발동하지 않는다.

## 7. 내 장수 목록과 전체 무장 조회

### 내 장수

- 오른쪽 정보 영역에 **‘내 장수’** 탭을 추가한다. 지도 높이를 줄이거나 기존 채팅 입력창을 가리지 않는다.
- 각 항목에 초상·이름·실제 D등급·효과 티어·**현재 주둔 영토**·행동 가능/남은 대기·효과 한 줄을 표시한다. 예: `조운 / D12 / S / 성도 / 이동 가능 / 패전 탈출 2회 남음`.
- 정렬: 현재 영토 → 실제 D등급 → 이름. 이름 검색과 등급·행동 가능 필터를 제공한다. 설정은 해당 기기에만 저장한다.
- D20은 ‘내 군주’로, 이름 없는 보존 병력은 ‘기존 동급 병력 / 고유 효과 없음’으로 구분해 포함한다. 이들을 역사 무장 100명 수에 합산하지 않는다. 복귀 대기 병력은 위치 ‘복귀 대기’·효과 비활성·자동 복귀 예정으로 표시하며 직접 이동 버튼을 비활성화한다.
- 목록에서 위치를 누르면 지도만 해당 영토로 이동한다. 장수를 누르면 상세·이동을 열고 그 병력 ID 하나를 선택한다. 포인터 클릭과 키보드 선택 모두 지원한다.
- 상세에는 효과명·조건·수치·담당·준비 시간·남은 생존/호위 횟수·누적 성장·재사용 대기를 필요한 항목만 표시한다. 전사해 사라진 개체의 효과 상태를 같은 이름의 새 개체에 붙이지 않는다.

### 목록에서 바로 이동

1. 장수 선택 → 현재 위치와 인접한 내 영토 목록 표시.
2. 각 목적지에 `일반 이동 가능`, `D4 1명과 교환`, `병사 부족`, `영토/병력 대기` 등을 구체적으로 표시.
3. 목적지 선택 → 출발·도착·교환 병력·예상 대기와 담당 해제 영향 표시 → ‘이동’ 1회 확정.
4. 이동 성공 시 목록 위치와 지도 강조를 갱신한다. 이동 후 같은 영토가 재클릭 해제로 오작동하지 않도록 정보 조회와 지도 선택을 분리한다.
5. 선택 중 다른 전투·충원·이동으로 상태가 바뀌면 오래된 명령을 강제로 실행하지 않고 새 상태와 불가 사유를 표시한다.

### 전체 ‘무장 100인’

- 기존 정적 갤러리를 현재 전황과 연결한다. 각 이름은 `미등장 / 현재 주둔 영토 또는 복귀 대기 / 소유 군주`로 조회한다. 이 게임의 기존 공통 전황에 이미 공개된 위치만 사용하며 새로운 정찰·안개 시스템을 만들지 않는다.
- 새 충원 대기 후보는 ‘미등장’으로 표시한다. 전체 과거 사망 명부를 새로 축적해 ‘전사’와 ‘한 번도 미등장’을 영구 구별하는 기능은 추가하지 않는다.
- 내 소유이면 상세와 바로 이동을 제공한다. 다른 참가자 무장은 위치·설명 조회만 제공한다. 로그인 전 화면에서 기존 읽기 권한을 확대하지 않는다.
- 현재 보유 위치·이동 가능 판단은 저장 확정된 전황을 기준으로 하고, 오프라인 충원 예상은 별도 ‘충원 예정’으로 표시한다. 아직 확정되지 않은 무장을 소유한 것처럼 이동시키지 않는다.

## 8. 꽉 찬 영토의 장수·D4 교환 이동

### 추천 대상과 기본 조건

- 인접한 내 소유 영토끼리만 허용한다. 역사 장수 D6·D8·D12 및 기존 이름 없는 동급 병력을 대상으로 하며 **군주 D20도 포함하는 것을 추천 기본값**으로 둔다.
- 적·중립 영토는 기존 공격으로 처리한다. 교환 이동으로 승패 판정을 건너뛰지 않는다.
- 목적지에 여유가 있으면 일반 이동. 교환이 필요한 경우에는 양쪽에서 병력이 출발하므로 **양쪽 영토 행동 대기와 이동 병력·반환 D4의 행동 가능 상태를 모두 검사**한다.
- 교환으로 반환할 D4는 행동 가능한 개체 중 병력 ID 순으로 자동 선택하고 확인창에 수를 표시한다. 대기 중인 D4를 강제로 꺼내거나 대기 시간을 단축하지 않는다.

### 다수 병력 처리

`여유 칸 = max(0, 현재 유효 정원 - 목적지 병력 수)`

`필요 교환 수 = max(0, 보내는 전체 병력 수 - 여유 칸)`

- 필요한 교환 수만큼 **보내는 장수/군주**가 있어야 하며, 목적지에 행동 가능한 D4도 그만큼 있어야 한다.
- D4 동행은 원래 여유 칸에 들어가는 범위에서 허용한다. 장수 한 명을 끼워 넣어 일반 병사를 무제한 교환시키지 못한다.
- 모두 가능해야 한 번에 처리한다. 일부만 이동시키거나 선택 병력을 조용히 바꾸지 않는다.

| 상황 | 처리 |
| --- | --- |
| 목적지 가득 참, 장수 1명 이동, 준비된 D4 있음 | 장수 1명과 D4 1명 자리 교환 |
| 목적지 가득 참, 장수 2명 이동, 준비된 D4 1명 | 전체 이동 불가. D4 1명 부족 안내 |
| 여유 1칸, 장수 2명 이동 | 1명 일반 이동 + D4 1명 교환 |
| 여유 1칸, 장수 1명 + D4 1명 이동 | D4는 여유 칸 사용, 장수는 D4 1명과 교환 |
| 목적지 가득 참, 장수 1명 + D4 1명 이동 | 필요한 교환 2명 > 장수 1명. 전체 이동 불가 |
| 목적지 가득 참, D4만 이동 | 기존처럼 이동 불가 |
| 출발지에 장수 1명뿐이고 목적지 D4와 교환 | 교환 후 출발지에 D4 1명이 남으므로 허용하는 추천 기준 |
| 출발지에 장수 1명뿐이고 목적지에 빈자리 있음 | 반환 D4가 없어 출발지가 비므로 일반 이동 불가 |

### 완료 후 상태

- 출발지 최종 병력은 `기존 - 이동 + 반환 D4`이며 최소 1명이어야 한다. 이 최종 상태 검사는 교환 이동에만 적용하고 공격의 최소 잔류 규칙은 바꾸지 않는다.
- 두 방향 이동을 같은 저장에서 처리한다. 개체 ID·등급·효과 생애 상태·총 병력 수를 보존한다.
- 교환 양쪽 영토는 기본 10분 행동 대기. 정방향 장수는 적용 가능한 기동 특기가 있으면 해당 병력 대기만 줄일 수 있고, 반환 D4는 기본 10분이다. 간옹을 기동 담당으로 고르면 해당 효과 조건에 따라 반환 D4 1명만 8분으로 줄인다. 기존에 더 긴 대기가 있다면 줄이지 않는다.
- 교환은 생존 횟수·승리 횟수·신규 충원·처치·전사·부활 재료 사용으로 세지 않는다.
- 목적지 내정 담당은 자동 교체하지 않는다. 온 장수에게 담당을 맡기려면 담당 변경을 별도로 실행한다. 떠난 담당의 정원 효과가 사라져도 병력을 삭제하지 않는다.
- 정원 효과를 잃어 이미 초과 주둔인 곳도 병력 수를 늘리지 않는 동수 교환은 허용한다. 순증 이동은 차단한다.

## 10. 저장 구조·동시 처리·Firebase 규칙

### 새 저장 구분

| 위치 | 추가/변경 내용 |
| --- | --- |
| 전장 | `featureVersion:3`, `rosterVersion:2`, `effectsVersion:1`, 전환 시각. 명령 `protocol:3` |
| 전장 무장 색인 | 역사 무장 ID → 생존 개체 ID·소유 군주·위치 종류(주둔/복귀 대기)·해당 위치. 최대 100개. 실제 개체 저장을 원본으로 삼고 색인은 같은 저장에서 갱신 |
| 복귀 대기 | 소유 군주별 회수 병력·원래 영토·최초 회수 시각·현재 생애·고정 복귀 순서. 역사 무장 색인은 주둔 위치와 대기 위치를 구분 |

| 영토 | 내정 담당·수비 특기 2명·지원 대상·퇴각지·자리 변경 가능 시각·준비 시각·다음 충원 시각·주기 정보 |
| 이동 사건 | 장수 ID·이름·등급·출발·도착·교환 수. D4 개별 복귀 사건은 만들지 않음 |
| 전투 사건 | 원래 눈·효과별 보정·최종 점수·소모 횟수·실제 전사·탈출. 최신 100개 사건 범위 안에서 유지 |

- 효과 상태는 장수 이름이 아니라 **개체 ID**에 묶는다. 다시 등장한 동일 이름의 새 개체에 이전 생애 상태를 복사하지 않는다.
- 손권 효과가 있는 대거점 최대 23명을 지원한다. 저장의 기본 상한도 영토별 기본 정원 +3으로 제한한다. 효과를 잃었을 때의 정원 초과도 이 물리 상한 안에서 유효 저장으로 읽는다.
- 전체 무장 색인은 빠른 조회와 충원에 사용하지만 서로 다른 이름을 동일 개체에 붙이거나 같은 이름을 두 병력에 붙이는 저장을 정상화 함수가 거부하게 한다. 이 검사는 주둔 배열과 복귀 대기 목록을 합쳐 수행하며 같은 개체가 둘 다에 존재할 수 없다.
- 병력 배열 위치는 이동·전사로 바뀌므로 색인은 안정적인 개체 ID와 현재 위치를 함께 대조한다. 배열 순번을 개체 신원으로 쓰지 않는다.
- 생존 병력 조회를 공통 함수로 모아 주둔과 복귀 대기를 함께 검사한다. 군주 생존·부활 가능 여부·전체 병력 집계·무장 후보 제외가 서로 다른 기준을 쓰지 않게 한다. 내정·전투·직접 이동에는 주둔한 실제 병력만 사용한다.

### 공통 처리와 권한

- 한 명령이 충원 정산·이름 예약/해제·교환·효과 상태·통계·전황·전령 채팅을 한 번에 확정하도록 현재 다중 경로 갱신과 버전 검사를 확장한다.
- 충원 예정 시각과 준비 완료 시각을 사건으로 계산한다. 화면 초 단위 숫자 갱신을 서버 쓰기로 만들지 않는다.
- 모든 계정이 다른 사람의 병력을 자유롭게 바꾸도록 권한을 넓히지 않는다. 공유 정산은 허용된 충원·정해진 내정 상태 변화・복귀 대기 자동 배치만, 전투 퇴각은 해당 전투의 지정 병력과 목적지만, 교환은 같은 소유자의 양쪽 영토만 허용한다.
- 승인 없는 시작에 한해 선정된 기존 소유자의 병력 회수·복귀 대기 저장과 영토 소유권 변경을 허용하는 별도 명령 경로를 만든다. 중립 0곳 조건, 시작 자격, 실제 영토 수 1위의 소유권, 개체 보존과 단일 대상 재배정 범위를 검사한다. 기존 임의 승인 권한을 재사용해 전 영토 쓰기를 열지 않는다.
- 복귀 대기 병력의 직접 출전·효과 발동·부활 재료 사용·중복 생성·다른 소유자 대기열 쓰기를 막고, 대기열 감소와 주둔 배열 증가가 같은 개체의 자동 복귀로 연결되는지 검사한다. 승인 요청·승인·거절은 새 프로토콜에서 거부한다.
- Firebase 규칙은 무장 ID·이름 대응, 유일성 색인과 병력의 결합, 명령자·소유권·대기 범위·개체 등급·횟수의 형태·증가 한도 및 전장 버전을 검사하는 방향으로 생성한다.
- 이전에 사용한 RTDB 제약을 따른다. 규칙에서 지원하지 않는 `numChildren()`을 도입하지 않고 최대 23칸의 연속 배열·상한 검사를 생성한다. 상수 20칸 검사를 남겨 두지 않는다.
- `readyAt` 최대 20분과 준비·재사용 시각을 혼동하지 않는다. 12/24시간 특기 대기는 별도 필드로 제한한다. 정수 범위·최대 횟수·불필요한 추가 필드도 검사한다.
- 기존 지인 신뢰형 클라이언트 전투는 유지한다. 이 업데이트가 변조된 클라이언트의 모든 난수 조작을 막는 서버 판정으로 바뀌었다고 안내하지 않는다.

## 11. 예상 승률·화면 표시의 정확성

- 특기가 없는 전투는 기존 정확한 주사위 승률 함수를 유지할 수 있다. 특기가 활성화되면 실제 전투와 같은 효과 계산 함수를 호출해 예상 승률을 구한다.
- 특기 조합의 복잡한 확률은 별도 난수 영역에서 고정 표본(초기 기준 8,192회)으로 추정하고 **‘예상 승률 약 N% · 무장 효과 반영’**으로 표시한다. 실제 전투 씨앗·결과를 미리 사용하지 않는다.
- 계산은 입력 변화 때만 실행하고 이전 전황 결과를 버린다. 휴대폰에서 지연이 크면 작업 스레드 또는 비동기 청크로 옮긴다. 화면 렌더링마다 반복 계산하지 않는다.
- 전투 전에는 참가 특기·현재 발동 조건·생존과 호위의 선택 대가를 보여준다. 결과에는 기본 합계 → 눈 보정 → 공격 감산 → 최종 특기 보정 → 최종 점수를 구분한다.
- 생존 확률은 승리 확률에 포함하지 않는다. ‘패배해도 탈출 가능’은 별도 안내한다. 예상 승률이 높은 전투에서 실제 패배가 나오더라도 오류라고 표시하지 않는다.

### Firebase 에뮬레이터·동시 접속

- 15명의 정산, 같은 마지막 무장 동시 획득, 두 참가자의 마지막 중립 영토 시작, 중립 소진 직후 1위 영토 동시 배정·최신 순위 재계산, 교환 목적지 동시 이동·공격, 생존 퇴각 공간 경합을 검증한다.
- 시작 재배정과 다른 군주의 충원·공격·이동이 겹쳐도 원주인 병력이 중복되거나 사라지지 않는지 검사한다. 회수 전후 기존 개체 집합이 같고, 전장 전체 생존 병력 증가는 시작 병력 5명뿐이어야 한다. 자동 회수로 처치·전사·무장 등장 사건을 만들지 않는다.
- 채팅 전송과 충원/전투/업데이트 공지가 겹쳐도 게임 변경과 사건이 함께 저장되고 채팅은 최신 50개만 남는지 확인한다.
- 구버전 명령·가짜 이름 예약·다른 사람 담당 변경·고유 효과 횟수 초기화·임의 병력 증식·무관한 퇴각 영토 쓰기·범위 밖 배열/시간/수치를 거부하는지 확인한다.
- 재시도할 때 사용자가 선택한 두 영토나 참전 병력이 바뀌면 새 확인을 요구한다. 단순 전장 버전 경합만이면 최신 상태로 재계산한다.
- 테스트는 실제 전장 대신 `demo-samguk-online`에서 수행한다.

### 화면과 실행

- PC 1366×768·1440×900·1024 폭, 휴대폰 390 폭에서 두 지도 테마, 내 장수 목록·검색·필터·상세·직접 이동·교환 확인·키보드 조작을 확인한다.
- 화면 열린 중 충원·사망·이동·시작 재배정·교환·복귀 대기/자동 복귀가 일어나도 현재 위치와 담당·남은 대기가 갱신되는지 확인한다. 시작에 승인 요청·승인·거절 버튼이 남지 않았는지 확인한다.
- 고유 효과 없음/대기 중/미지정/조건 미충족/사용 완료를 구분한다. 확정된 위치와 예상 충원 표시를 혼동하지 않는다.
- 실제 저장을 불러온 별도 로컬 복제본에서 시작·이동·공격·군주 부활·탈락·재참가를 실행한다. 운영 저장에 테스트 병력을 만들지 않는다.
- `npm test`, `npm run test:rules`, `npm run build`를 실행하고 생성 결과의 주요 화면도 확인한다. 이번 문서 작성만으로 위 검증을 통과했다고 보고하지 않는다.

## 15. 운영 반영 순서와 전체 공지

1. 코드와 생성 규칙을 에뮬레이터에서 함께 검증한다. 개발용 최신 백업 사본으로 이관 전후 대조표를 만들고 실제 참가자 정보는 공개하지 않는다.
2. 구버전/신버전 전환 규칙과 짧은 점검 표시를 준비한다. 새 사이트가 아직 이전 저장을 읽을 때 ‘업데이트 준비 중’으로 안전하게 대기하도록 한다.
3. 새 화면을 배포한 뒤 점검 동안 일반 전장 쓰기를 차단하고, 운영자 연결로 최신 저장을 다시 확보한다. 채팅 경로를 오래된 백업으로 덮어쓰지 않는다.
4. 정해진 전환 시각까지 기존 규칙의 미정산 충원을 먼저 반영하고, 단 한 번 이관해 새 이름 색인·효과 상태·새 주기와 빈 복귀 대기 구조를 설정한다. 이전 미처리 승인 신청은 취소 상태로 마감한다. 과거 미접속 시간을 새 확률로 소급 추첨하지 않는다.
5. 새 버전 필수 필드·수량·색인과 규칙을 확인한 후 점검을 해제한다. `protocol:2` 등 구버전 쓰기는 거절하고 새로고침을 안내한다.
6. 로그인·내 장수 위치·교환 이동·충원·전투·전황·채팅이 실제 운영에서 정상인지 최소 범위로 확인한다. 확인하지 않은 기능을 완료라고 공지하지 않는다.
7. 고정 업데이트 ID로 **전체 알림·전황·전령 채팅에 변경 안내를 한 번만** 남긴다. 공지는 아래 핵심을 포함한다.

> 업데이트 완료: 중립이 없으면 영토 수 1위의 영토에서 승인 없이 무작위 시작합니다. 기존 병력은 원주인에게 복귀·대기합니다. 무장 유일성·새 확률·100인 효과, 내 장수 위치·바로 이동, D4 교환 이동을 적용했습니다. D6 충원·병사 이동 소식을 줄였고 기존 중복 병력은 등급을 보존했습니다. 새로고침해 주세요.

위 공지 문구는 실제 구현·검증한 범위에 맞춰 다시 확정한다. 구체적 확률도 구현값으로 함께 안내한다.

운영 재개 전에 실패하면 점검 상태에서 검증한 이전 전황과 호환 규칙으로 복구할 수 있게 한다. 운영 재개 후 플레이가 진행된 뒤에는 예전 전체 백업을 덮어쓰지 않는다. 새 진행을 보존하는 수정·복구 계획을 별도로 적용한다.
