# AI 군주 운영 업데이트 — 2026-10-30

사용자 승인 범위: 실제 Firebase 서버 배포, 시즌3의 2시간 간격 내부 등장, 시즌4부터 시작 군주 배치. Blaze 과금 가능성은 수용하며 비용 최적화는 유지한다.

## 적용 규칙

- 시즌3에는 시작 군주를 뒤늦게 주입하지 않는다. 활성화 전의 2시간 회차도 소급 실행하지 않는다.
- 시즌 개막 기준 2시간마다 영토15개 이상인 각 국가에서 내부 영토1곳을 추첨한다. 모든 인접지가 자국이어야 하며 보호 중·전투 중·군주 D20 소재지는 제외한다. 적합한 곳이 없으면 해당 국가는 건너뛴다. 진행 중 총수 상한은 없다.
- 원래 주둔 병력은 인접 자국의 빈자리 또는 복귀 대기로 보존한다. 새 군주는 D20 1명·D4 6명으로 내부 등장하며 기존 보호·행동 대기를 따른다.
- 이름은 지난 시즌 결과의 군주 이름을 재사용하고 현재 전장의 이름과 중복을 피한다. 계정·접속·대화를 사칭하지 않는다. 지도와 등장 소식에는 AI 접두어를 붙이지 않는다.
- 시즌4부터 중립지에 시작 군주1~5명(D20 1+D4 4)을 배치한다. 직전 시즌 우승 인간 군주는 종료 화면에서 개막 전까지 선택을 바꿀 수 있다. 미선택3명, 공동 선택은 낮은 중앙값을 쓴다. 이미 접속한 인간의 영토·병력은 보존한다.
- AI 판단은10분마다 수비 보강→유리한 공격→후방 보급·장수 이동·부활을 평가한다. 한 군주당 영토 행동 최대2회와 독립 장수 이동1회, 전체 판단35초 예산을 사용한다. 대기·정원·인접·전투 규칙은 기존 규칙을 그대로 적용한다.

## 운영 및 비용 절감

Firebase Functions Node22, asia-southeast1, 예약10분, 최소 인스턴스0/최대1, 실패 자동 재시도0. 논리적 2시간 경계 후 다음 예약 실행에서 등장하므로 실행 시차는 최대 약10분이다. 종료1시간 후 접속자가 없어도 다음 전장을 준비한다.

원본 `worlds/season-N`과 기존 요약 동기화를 유지했다. AI 전체가 현재 전장 스냅샷1개를 공유하며 AI별 다운로드나 DB 전체 루트 반복 읽기를 하지 않는다. 기존 전투 상세100개를 포함한 한정된 시즌 스냅샷을 서버가 읽는 비용은 발생할 수 있다. 완전한 별도 저장소 전환은 하지 않았다. 이전 격리 저장소는 검증용이며 실제 운영 경로가 아니다.

서버 판단 중 사람이 먼저 저장하면 revision 조건으로 AI 저장을 취소하고 다음 회차로 넘긴다. 처음 읽은 revision을 고정하여 재시도 중 최신 인간 명령을 오래된 결과로 덮지 않는다. 사람은 AI 운영 메타데이터를 변경할 수 없다. 서버 비밀 난수 키·환경 파일·운영 백업은 저장소에서 제외한다.

운영 제어는 `aiOperations/enabled`, 최초 적용 시즌은 `aiOperations/firstSeason=3`. 우승자의 다음 시작 수는 서버 호출로 검증해 `aiOperations/ballots/season-N`에 보관한다. 비용만으로 자동 중지하거나 요금제를 바꾸는 장치는 두지 않았다.

단위277개 통과. Firebase 기존83개·AI 호환2개의 검사에서 일반 명령, AI 상대 공격·점령, 메타데이터 위조 차단을 확인했다. 전체85개는 배포 CI에서 다시 실행한다. 서버 배포와 사이트 배포·활성화를 마친 뒤 운영 확인 결과를 아래에 기록한다. 운영 전장에 시험 공격·초기화는 하지 않는다.
