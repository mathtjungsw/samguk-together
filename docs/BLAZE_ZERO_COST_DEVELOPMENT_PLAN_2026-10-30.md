**현재 상태: Spark 임시 복귀 완료.** 사용자 결제 프로필 등록 후 Blaze 연결을 확인했으나, 기존 일별 다운로드가 무료량을 넘을 위험을 안내했다. 사용자가 ‘Spark로 잠시 복귀, 최적화 후 Blaze 재연결’을 선택해 전환했고 콘솔의 ‘요금제 변경이 완료되었습니다 / Spark $0/월’을 확인했다. 공통 비용 지침과 상세계획 작성 완료. **통신 절약1차는 구현·배포했고 [실행·검증 기록](./UPDATE_2026-10-30_COMPACT_SYNC.md)에 정리했다.** AI 서버·예약 작업·새 비용 알림·Blaze 재연결은 아직 적용하지 않았다.

기존 [AI 군주 상세계획](./AI_RULER_DEVELOPMENT_PLAN_2026-10-30.md)의 시작 수·등장·행동 알고리즘을 유지하되, 실행 환경은 **Blaze의 예약 함수**를 목표로 바꾼다. 이 문서가 비용·전송·실행 환경에 관해서는 이전 계획보다 우선한다. 사용자 목표는 무료 제공량 안에서 실제 청구0원이며, Blaze 연결이 무료 초과 사용에 대한 포괄 승인은 아니다.

## 2. 현재 구조에서 확인한 원인

`src/store.js`는 현재 전장 전체를 최초 불러오고 그 전장을 실시간 구독한다. 전황 본문과 전투 주사위 상세도 같은 전장 아래 있다. 실패 복구에서 전장·채팅을 다시 읽는 경로가 있으며 변경 비교 함수는 배열 변경 때 배열 전체를 저장한다.

**주의:** `onValue` 콜백이 전체 스냅샷을 준다고 해서 매 변경마다 전체 전장이 네트워크로 재다운로드된다는 뜻은 아니다. SDK의 변경분 동기화는 이미 활용 중이다. 개선 효과는 최초 접속·재접속·재시도·큰 배열 교체·여러 구독자를 구분해 실측한다.

콘솔 개요에서7일 다운로드 합계 약1.32GB, 저장량 약1.67MB 표시를 확인했다. 접근성 일별 표의 표시 기간은10월22~28일이고, 26일16.882M·27일449.839M·28일952.107M바이트였다. 27~28일은 현재 Blaze 무료 다운로드 일360MB를 넘는 수준이다. **이 과거 Spark 사용량에 소급 과금됐다는 의미가 아니며, 동일한 패턴이 Blaze에서 재현되면 무료량 초과가 예상된다는 뜻이다.** 사용자에게 이 위험을 즉시 안내했다. 당일 최신 사용량·확정 청구내역은 아직 조회하지 않았다.

7일 중 사용량이0인 날이 있으므로 평균을 전체7일로 나눠 무료 운영을 보장하지 않는다. 기존 사람 사용량만으로도 무료량을 넘을 수 있어, 새 AI보다 **기존 게임 다운로드 최적화와 최근 활동일 재측정이 선행**되어야 한다. 최적화 전 Spark 임시 복귀는 사용자 선택으로 완료했다. 연결 중 발생한 실제 비용 유무·확정 청구액은 이번에 조회하지 않았으며, Spark 복귀가 과거 비용을 취소한다는 뜻은 아니다.

## 4. 단계 A — 기록과 실시간 상태 분리

새 버전 전장에만 다음 역할 분리를 적용한다. 경로 이름은 구현 시 현행 규칙 생성기와 맞춰 결정한다.

| 데이터 | 읽는 주체·시점 |
| --- | --- |
| 시즌 메타: 현재 시즌·마감·종료·AI 다음 회차 | 실행기 먼저 소량 조회, 접속자는 상단 안내 구독 |
| 실시간 상태: 소유·병력·효과 상태·대기·예약·revision | AI 회차당 공유 조회1회, 단계 A의 기존 게임 클라이언트 |
| 전황 요약: 최근100건의 시각·당사자·종류·한 줄 문구 | 기존 전황·내 소식에 필요한 작은 구독 |

기존 기록100건 보존·채팅50건 보관 규칙을 줄이지 않는다. 지난 역사를 지우지 않는다. 동적 장수 효과 사용 횟수·고유 이름 예약·도착 시각 등 실제 판정 필드는 유지한다. 성능을 이유로 무장 효과를 생략하지 않는다.

전투 엔진이 현재 전장 형태를 받도록 저장 어댑터를 둔다. 과거 기록을 읽지 않아도 현재 명령을 판정할 수 있게 의존성을 분리한다. 관평 대기 결과·예약 병력은 실시간 상태에 보존해, 전투 상세를 나중에 읽는 구조 때문에 호위 선택이 깨지지 않게 한다.

## 5. AI 실행 — AI별 다운로드 금지

예약 작업1개가10분마다 실행한다. 같은 실행에서2시간 회차의 내부 등장도 검사한다. AI 수가 늘어도 예약 작업을 AI별로 생성하지 않는다.

```text
작은 실행 메타 조회
→ 종료·미개막·비용 보호 모드면 종료
→ AI 행동도 등장 검사도 필요 없으면 큰 상태 조회 없이 종료
→ 필요한 현재 상태를 한 번 읽고 모든 AI가 메모리에서 공유
→ 기존 알고리즘으로 후보·승률·보강·이동 계산
→ 최신 revision 검증 후 합법적인 결과를 묶어 확정
→ 변경된 경로·요약·새 기록만 저장
→ 읽기/쓰기 크기·시간·충돌 횟수의 작은 집계만 남김
```

- 후보 도시·승률 표본·AI 한 명·개별 행동마다 DB를 다시 읽지 않는다. 고유 무장 인덱스도 한 회차에서 공유한다.
- 별도 상태 다운로드를 전제로 한 명령별 대형 트랜잭션을 반복하면 오히려 비용이 증가한다. 회차당 제한된 배치와 고정 사건 ID로 처리하고, 실제 SDK 전송량을 검증한다.
- 전체 실시간 상태의 revision CAS가 필요한 최소 범위를 기술 검토한다. 서버 임대와 배치 번호로 중복을 막고, 사람 명령과 충돌하면 최신 상태에서 최대2회 재시도 후 해당 회차의 남은 AI를 보류한다. 사람에게 전역 대기 잠금을 걸지 않는다.
- 정확한 판정이 어려우면 안전하게 회차를 건너뛴다. 이전 데이터로 결과를 강제로 쓰거나 다음 회차에 놓친 공격을 몰아치지 않는다.
- 함수 재사용 인스턴스의 캐시는 보조 수단이다. 매 실행이 새 인스턴스여도 성립하는 전송량으로 설계한다. 캐시가 있으면 revision/변경 세대를 확인한 경우에만 재사용한다.

## 6. 원자성·전투 기록 유실 방지

기록 분리 때문에 ‘점령은 됐는데 전투 기록은 사라지는’ 상태를 만들지 않는다. 실시간 상태 확정과 작은 미처리 사건 목록을 같은 조건부 확정 단위에 둔다. 큰 과거100건 기록은 이 확정 단위에서 제외한다.

- 현재 회차의 새 사건은 고정 ID로 후속 저장하며, 저장 성공 전에는 미처리 표시를 지우지 않는다. 전투 상세 payload가 필요하면 제한된 서버용 outbox에 보관한다. 일반 클라이언트는 outbox의 부모를 구독하지 않는다.
- 실행기 중단 후 다음 실행은 이전 미처리 사건을 먼저 복구한다. 복구한 사건은 다시 공격하지 않는다. 기록·채팅·요약 저장은 사건 ID 기준으로 중복을 막는다.
- outbox 전체를 과거 기록처럼 계속 쌓지 않고, 정해진 작은 크기·사건 수를 넘으면 새 AI 행동을 멈추고 복구를 우선한다. 이미 확정된 상태와 기록은 삭제하지 않는다.
- 이 구조가 과도해지면 최초 버전에서는 영수증은 유지하고 전투 상세 분리만 적용한다. 더 작은 전송량보다 저장 안전성을 먼저 검증한다.

## 7. 접속 화면의 다운로드 절감

단계 A에서는 실시간 상태 구독을 유지하고 큰 전투 상세만 분리해 변경 범위를 줄인다. 연결 직후 `get`과 listener 초기화가 중복 다운로드를 일으키는지 실측하고, 최초 동기화 완료 경로를 하나로 합친다. SDK 캐시 때문에 이미 중복 전송이 없는 경우 절감을 과장하지 않는다.

- 같은 경로를 여러 UI가 각각 구독하지 않고 중앙 저장소의 메모리 상태를 공유한다. 매초 타이머는 로컬 표시만 갱신한다.
- 오류 때 즉시 전장 전체·채팅 전체를 연속 재조회하지 않는다. 연결 단절/권한/실제 revision 충돌을 구분하고 지수 대기·단일 진행 요청·재시도 상한을 둔다.
- 도감·역사·전투 상세는 열 때만 조회하고, 닫으면 불필요한 구독을 해제한다. 같은 사건은 기기 내 캐시를 재사용한다. 로그아웃·시즌 변경 시 다른 계정의 비공개 초안·명령 상태는 분리한다.
- 선택 도시·지도 확대·도감 스크롤은 기존처럼 유지한다. 구독 축소가 화면 깜빡임이나 자동 선택 해제를 만들지 않게 한다.

## 8. 단계 B — 필요한 도시만 읽는 지도

단계 A의 실제 전체 프로젝트 사용량을 보고 채택한다. 지도에는90도시의 소유자·병력 수·정원·표시용 대기 같은 작은 요약만 보낸다. 병력 개체·효과 사용 기록은 내 도시/선택 도시/행동에 필요한 인접 도시에서만 읽는다. 전투 승률에 인접지원이 있으면 그 도시까지 포함한다.

목표는 대표 전장(친구15명·시작 AI5명)에서 지도·랭킹 최초 요약을 압축 전30KB 이내로 만드는 것이다. 확인 전 달성했다고 보고하지 않는다. 정적 이름·초상을 동적 요약에 중복 저장하지 않는다.

**서버로 모든 사람 명령을 옮기는 것이 항상 더 저렴하지는 않다.** 예를 들어 명령300회마다 서버가274KB를 읽으면 약82MB/일이 추가된다. 기존 브라우저 캐시 계산보다 전체 전송량이 증가할 수 있다. 단계 B는 필요한 도시만의 동등한 판정·캐시·원자성 검증과 총량 계측 후에만 진행한다. 현행 순수 엔진을 전면 재작성하는 것을 기본 전제로 삼지 않는다.

필요하면 현재 판정에 필요한 데이터 묶음을 정의하는 명령별 read-set 어댑터를 만든다. 무장 효과·퇴각·전체 이름 예약·복귀 대기 정산의 누락이 있으면 작은 읽기를 포기하고 정확한 상태를 읽는다. 작은 지도 요약은 같은 정당한 명령에서 갱신하며 별도 상시 폴링으로 만들지 않는다.

## 9. 전송량을 오히려 늘리는 구현 금지

- 매초/매분 전장 전체 폴링, AI마다 상태 다운로드, 후보마다 Firebase 승률 계산 요청 금지.
- 상태의 루트에 매번 현재 시각·heartbeat·비용 카운터를 써서 모두에게 전송하지 않는다. 실행기 운영 정보는 별도 비공개 경로에 낮은 빈도로 집계한다.
- 매 행동마다 병력 전체의 순서를 바꾸거나 전체 전장 `set`을 하지 않는다. 기존 도시 단위 배열 교체부터 크기를 측정하고, 실제로 필요할 때만 unit ID별 사전 형식으로 바꾼다.
- 매번 DB 전체를 백업·내려받아 검사하지 않는다. 백업·복구는 승인한 배포 시점과 필요한 범위에서 한다.
- 작은 REST 호출을 수백 개로 쪼개 TLS·헤더·왕복 비용을 키우지 않는다. 재사용 연결·병렬 묶음과 좁은 SDK 읽기를 비교한다.
- RTDB JSON을 통째로 base64/압축 문자열에 넣는 방식은 변경분 동기화·보안 규칙·부분 읽기를 깨뜨리므로 기본안에서 제외한다.
- 기존 Google 로그인·주체별 쓰기 권한·고유 장수 예약 검증을 비용 때문에 풀지 않는다.

## 10. 서버 실행 비용 설정

- 기본 예약 함수:10분 간격1개. 최소 인스턴스0, 최대 인스턴스1, 회차 중복 실행 잠금. 최대 인스턴스만으로 비용이 차단된다고 설명하지 않는다.
- 초기 메모리256MiB를 측정하고 부족하면 필요한 만큼만 조정한다. timeout60초 이내 목표와 CPU/메모리 시간 예산을 둔다. 무료 제공량을 호출 횟수만으로 판단하지 않는다.
- 이미 계산하는 알고리즘의 후보 수·표본 수를 제한하고, 비용 보호 모드에서 새 공격 판단을 보류할 수 있게 한다. 실제 전투 결과·이미 발동한 효과를 변경하지 않는다.
- 함수·DB 리전을 가능한 한 가깝게 배치하되, 실제 리전별 무료량·전송 가격은 배포 시 다시 확인한다. 기존 DB 리전을 비용 절감 명목으로 옮기지 않는다.
- 운영 로그에는 스냅샷·전투 주사위 전체를 반복 출력하지 않는다. 회차·소요 시간·크기·실패 코드만 남기고 보관 기간을 짧게 설정한다. 빌드 이미지 보관 정책도 확인한다.
- AI 예약 함수만으로 관평10초 구조나 시즌 정각 전환을 정확히 실행한다고 하지 않는다. DB에 기록된 마감 시각으로 판정하고, 별도 정각 실행이 필요하면 추가 예약/작업의 호출·비용을 먼저 산정한다. 함수 안에서10초~1시간 잠들며 기다리는 구현은 금지한다.

## 11. 무료량 접근 알림과 보호 모드 — 구현 예정

목표는 **이미 과금된 뒤 비용을 알리는 것보다 무료 한도 안에서 미리 알리는 것**이다. 단위는 공식 무료량의 해당 집계 기간과 맞춘다. RTDB 일별 무료량의 일 경계는 콘솔/문서로 확인해 한국 자정으로 임의 해석하지 않는다.

| 추천 기준 | 처리 |
| --- | --- |
| 기능 활성화 전 | 기존 사람 사용량+예상 AI+오버헤드의 활동일 예상치가 무료량70% 이내인지 확인. 예측 불가·초과 예상이면 먼저 안내하고 AI 활성화 보류 |
| 무료량60% 또는 조기 초과 예상 | 운영자 화면에 실제값·기간·추정치를 알림. 같은 알림 반복 금지 |
| 무료량75% 또는 근시일 초과 예상 | 새 AI 전투·등장 같은 추가 자동 작업을 보수적으로 축소/일시 보류하고 안내. 사람의 결과·병력은 보존 |
| 무료량85%·측정 데이터 장기 누락·실제 청구 감지 | AI 자동 행동 중지. 원인과 선택 가능한 무료 대안을 사용자에게 알림. 자동 재개는 검토 후 |

이 값들은 사용자 취향이 아니라0원 목표를 위한 초기 추천 안전 여유이며 계측 후 더 보수적으로 조정할 수 있다. AI 총수 상한을 새로 만들지는 않는다. 보호 모드로 보류된 등장·공격은 나중에 누적 실행하지 않고 전황에 운영 상태를 남긴다.

AI를 멈춰도 사람들의 사용량만으로 DB 한도를 넘을 수 있다. 앱 전체 읽기전용화·전체 서비스 차단·결제 해제를 자동으로 수행하지 않는다. 그런 조치가 필요할 것으로 예상되면 미리 사용자에게 알리고 별도 결정을 받는다. 따라서 이 설계만으로 청구0원이 강제 보장되지는 않는다.

## 12. 알림의 실체와 한계

- 운영자 화면의 한도·예측 표시와 Cloud Billing 공식 이메일 알림을 구현 시 구성한다. Codex가 대화 밖에서 계속 감시한다고 약속하지 않는다.
- 운영 추정값은 함수 읽기·쓰기 바이트·실행 시간을 낮은 빈도로 집계한다. 실제 무료량 판단은 RTDB 콘솔/Monitoring의 다운로드·기존 서비스 사용량과 대조한다. 앱 JSON 크기만으로 청구 사용량을 대체하지 않는다.
- 전체 프로젝트 사용량을 얻는 모니터링 호출·권한·지연·그 자체의 비용을 먼저 검토하고 과도한 조회를 하지 않는다. 측정이 오래 끊기면 자동 사용을 늘리지 않는다.
- 금액 기반 예산은 매우 낮은 금액의 경고 장치로 구성 가능 여부를 확인한다. 0원 입력 가능 여부를 확인하기 전 ‘0원 하드캡’을 설정했다고 하지 않는다. 예산 금액을 사용자가 지출해도 된다고 승인한 액수로 해석하지 않는다.
- 공식 문서상 일부 Firebase 서비스에는 Preview 지출 상한이 있으나 RTDB는 현재 대상 목록에 없고, 지원 서비스도 보고 지연 중 초과분은 청구될 수 있다. Cloud Functions의 지원 여부·화면 제공·제외 비용을 확인하고 보조 장치로만 사용한다.
- 현재 상태: 위 런타임 한도 알림·보호 모드·예산/지출 상한은 **계획이며 아직 실제 설정·배포하지 않았다.**

## 13. 작업 순서

1. 공통 비용 원칙 저장·사용자 결제 프로필 등록·콘솔 Blaze 확인·위험 안내·사용자 선택에 따른 **Spark 임시 복귀 완료**.
2. 구현 지시 후 당일·최근 활동일 사용량, 실제 무료량 집계 범위, 기존 예산 알림을 확인하고 기준선 저장. 과거450/952MB 피크가 있어 기존 게임 최적화를 새 AI 활성화보다 우선한다.
3. 에뮬레이터에서 기록 분리·초기 동기화/재접속 최적화 구현. 데이터 ID·순서·전투 다시보기·기존 시즌 호환 검증.
4. AI 공유 읽기·배치 확정·사건 복구와 무인 실행 구현. 대표·대규모 사례의 총 전송량·CPU 계측.
5. 공식 알림·운영자 한도 화면·보호 모드를 먼저 준비하고 정상·경계·측정 누락을 검증.
6. 기존 게임 최적화 배포·최근 사용량 실측 후, 기존 사용량+AI 예상량+여유분이 무료량 아래임을 설명하고 **Blaze 재연결**한다. 이 조건을 만족하지 못하면 사용자에게 알리고 Spark를 유지한다. 실제 청구를 수반하는 변경의 필요한 확인 절차는 별도로 따른다. 이후에만 예약 AI 활성화. 진행 시즌을 초기화하지 않고 이후 새 시즌에 적용.
7. 계측에서 필요한 경우에만 단계 B를 추가. 실제 개선이 없으면 복잡한 구조 변경은 하지 않음.
8. 승인 범위의 배포 후 PC·모바일·저장·전황/채팅 안내 확인. 실제 청구 상태·전송량은 운영 초기 다시 대조.

## 14. 검증·완료 기준

- 로그인을 반복하거나 전황 탭을 열지 않아도 과거 전투 상세355KB를 매번 읽지 않음. 한 사건 재생은 그 사건1건만 읽음.
- AI1/5/20명 및90영토를 나누는 극단 사례에서 AI마다 DB 초기 전장을 중복 조회하지 않음. 회차 중단·재시도·사람 동시 명령 때 병력/전투/중복 등장 불일치 없음.
- 네트워크 하위 계측으로 초기·유휴10분·전투·채팅·도감·재접속·관평·시즌 전환의 바이트를 각각 보고. 프로파일러 추정과 청구 콘솔 사용량을 혼동하지 않음.
- 무장 이름/등급/효과 사용 횟수, 전투확률/피해/퇴각,10분 이동/충원, 정원, 기록100건·채팅50건·지난 역사 보존 확인.
- 비용 기준60/75/85%, 예상 초과, 지연 지표, 반복 경고 억제, AI 중지 후 데이터 보존 검증. 실제 돈을 발생시켜 시험하지 않고 모의 지표로 경계를 검증.
- 기존 게임·Firebase 회귀 검증과 화면 검증 후 배포. 문서만 수정하는 이번 턴에는 불필요한 게임 테스트를 실행하지 않음.
