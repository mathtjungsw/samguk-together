# 공격·이동 결과 지연 조사 · 2026-11-02

사용자 확인: 공격·이동 버튼을 누른 뒤 결과가 나오는 구간이 느리다. 이번 작업은 읽기 전용 조사와 개선안 기록이다. 게임 코드·서버 설정·운영 전황은 변경하지 않았다.

## 확인한 운영 자료

- 조회시각: 2026-11-02 19:40~19:43 KST.

운영 Cloud Functions 메타데이터에서 campaignOrder의 ACTIVE 상태와 CPU0.1666 / 메모리256Mi / 최소인스턴스0 / 최대인스턴스1 / 인스턴스당 동시 요청1을 직접 확인했다. 함수 갱신시각은19:35:39 KST다. 여러 요청이 겹치면 대기할 수 있고 유휴 후 첫 요청의 시작 지연 가능성도 있다. 이번 표본에서 그 기여도를 따로 확정하지는 못했다.

## 코드 경로

1. 클라이언트에서 명령을 직렬 실행하고 서버에 전송한다. 실제 미확인 명령이 있을 때만 사전 재조회하며, 정상 새 명령에 복구용 사전 읽기를 매번 추가하지 않는다.
2. 서버는 전체 전장의 트랜잭션, 정규화/규칙 검사/충원·전투 처리와 기록 피드 갱신을 완료한 뒤 응답한다. 일부 공지 명령은 채팅 반영도 기다린다.
3. 클라이언트는 성공 응답 뒤 retryRead에서 전황과 채팅을 다시 확인할 때까지 기다린다. 그동안 화면의 명령 버튼은 처리 중으로 남는다. 이 구간의 사용자 단말 실측은 하지 못했다.
4. 새 세력명은 이미 받은 데이터로 계산한다. 신규 DB 읽기/서버 판정 경로는 추가하지 않았다. 공지 식별자 갱신 때문에 함수 재배포는 수행했다.

## 지도 계산 대조(참고)

실제 저장 사본의 활동 세력9개를 이용해 새 지도와 직전 지도를 동일한 Node/linkedom DOM 환경에서 비교했다. 각80회 갱신의 중앙값은390px에서1.21→1.71ms,1280px에서1.30→1.76ms였다. 실제 모바일CPU·브라우저 Canvas/페인트를 포함하지 않은 대리 측정이므로 단말 성능이나 체감 지연의 상한으로 해석하지 않는다. 브라우저 연결 비활성 상태여서 단말의 클릭~완료 전체 시간은 계측하지 못했다.

## 대기 개선안과 우선순위

1. 성공 응답에 이미 있는 확정 전투 결과를 먼저 표시하고 후속 화면 동기화와 분리한다. 다음 명령은 최신 전황 확인 전까지 계속 보호해 오래된 상태로 공격하지 않게 한다.
2. 실시간 동기화가 이미 해당 명령의 완료/새 순번을 확인했다면 불필요한 전황·채팅 재조회를 생략한다. 미확인 요청의 기존ID 재시도와 전적/보상 보존은 유지한다.
3. 서버의 반복 정규화·전장 전체 처리에서 중복 계산을 찾고 줄인다. 저장 일관성·규칙 판정은 유지한다.
4. 부족하면 전체 지연을 서버 대기/규칙 계산/DB확정/클라이언트 재조회로 구분하는 최소 표본 계측을 추가한다. 불필요한 상시 로그와 게임 내용 수집을 늘리지 않는다.
5. 실측 후에도 서버 자원/대기열이 병목이면 CPU나 인스턴스 수 조정을 검토한다. 비용 증가 가능성은 안내하고, 별도 업데이트 지시 범위에서 시행한다. 이번 조사에서는 요금제·자원 설정을 바꾸지 않았다.
