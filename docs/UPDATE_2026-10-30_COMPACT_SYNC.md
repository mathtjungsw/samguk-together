# 2026-10-30 통신 절약 1차 업데이트

상태: 통신 절약1차 구현·검증·운영 게시 완료. 최신 전체 계획의 첫 단계이며 AI 군주·유료 실행 활성화 완료를 뜻하지 않는다.

## 변경

- 원본 전투와 현재 전장의 구조를 삭제·초기화하지 않고, 검증된 작은 전황 요약을 별도로 저장한다. 전투 주사위·병력 개체 복사본은 결과 다시보기에서 해당 사건만 조회한다.
- 전장 전체의 루트 구독을 ‘history 이전/이후’의 두 키 범위 쿼리로 바꿨다. 큰 원본 기록은 초기·상시 동기화에서 제외하고, 두 범위의 command/revision/at가 일치할 때만 상태를 공개한다. 모르는 기존 필드도 범위에 포함돼 조용히 삭제하지 않는다.
- 요약과 원본의 명령은 같은 다중 경로 업데이트로 저장한다. 서버 규칙이 원본에 없는 사건·수정한 전투 점수·다른 내용의 요약을 거부한다. 별도 요약만 단독으로 덮어쓰는 쓰기도 거부한다.
- 구버전 클라이언트가 쓴 명령 때문에 요약 revision이 뒤처지면, 해당 revision은 원본 기록을 읽는 호환 경로를 사용한다. 모든 사용자가 새로고침하기 전에는 절약 효과가 줄 수 있지만 전황을 숨기거나 병력을 초기화하지 않는다.
- 영수증·고유 장수 예약·병력 대기·관평 고정 결과는 유지한다. 명령 재시도·실시간 조합·시즌 경계에서 기존 엔진을 그대로 검증한다.
- 다시 본 전투는 기기 메모리에 최근12개까지 캐시한다. 장수·도감·지도 선택·랭킹·채팅 정책은 유지한다.
- 운영 브라우저 계측으로 종료된 시즌 조회와 이미 존재하는 다음 시즌 확인용 트랜잭션이 큰 원본을 읽는 경로를 발견해 수정했다. 현재 시즌을 찾을 때 종료 메타·기존 공개 이름·다음 revision만 읽으며, 다음 시즌이 없을 때만 생성 트랜잭션을 사용한다. 기존 시즌을 찾는 과정에서 기록·병력을 미리 읽지 않는 회귀 검증을 추가했다.
- 실제 WebSocket 프레임에서 최초 get과 구독 시작이 같은 상태를 각각 전송하는 것을 확인했다. 최초 읽기부터 두 상태 범위+요약의 구독3개를 공유하도록 바꿨고, 재시도에서도 이 구독을 재사용한다. 쿼리 프레임 사이의 짧은 도착 차이 때문에 구버전으로 오인해 원본을 읽지 않도록350ms 유예를 두되, 실제 구버전 쓰기는 원본을 읽어 보존한다.

## 검증·배포 기록

단위249개·Firebase81개와 빌드를 검증했다. 운영 규칙을 게시 후 다시 읽어 로컬 규칙과 일치함을 확인했다. 기존 규칙은 release ID를 제외하면 동일하고 요약 검증만 추가했다. 운영 시즌3의 Google 자동 연결·기존 영토/병력·전황/채팅/접속 알림·선택 전투1건 지연 조회·모바일 다시보기를 확인했다. 운영 전장에서 시험 공격·이동·초기화는 하지 않았다.

GitHub Actions [최종 검증·배포](https://github.com/mathtjungsw/samguk-together/actions/runs/41006351660)는 성공했다. 코드 커밋89eec1c, 운영 빌드8174a79fd9be이다.

최종 운영본을 Chrome에서 한 번 새로 접속해 연결 완료까지 관찰한 WebSocket 텍스트 프레임은38개, UTF-8 payload 합계308,851바이트였다. 상태 범위2개+요약 구독은 각1회였고, 범위 없는 전장 루트 조회와 원본 history 전체 조회는0건이었다. 전황의 결과 보기는 해당 전투 사건1건만 조회했고, 같은 사건을 두 번째 열 때 추가 상세 조회는0건이었다. 확인 시 콘솔 오류는 없었다.

이 계측은 한 차례 접속의 메시지 payload이며 TLS·연결 오버헤드, 인증 HTTP, 정적 자산, 이후 갱신을 포함한 하루 전체 청구량이 아니다. 구버전 이용자가 쓴 명령으로 요약이 뒤처지면 호환 조회가 다시 발생한다. 대표 활동일 사용량의 무료량 충족을 뜻하지 않는다.
