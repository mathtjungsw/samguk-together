# AI 군주 구현·검증 현황

**최신 사용자 결정 — 2026-10-30 오후:** Blaze 재활성화 완료. 사용자는 게임 운영 비용 발생을 수용하며, 비용 절감과 가능성 안내는 유지하되 비용 발생·예상만으로 개발·배포·AI 동작을 중단하지 않도록 지시했다. 무료량 사전 실측/70% 여유/비용 자동 중지 조건은 폐기한다. 코드의 비용 판단은 알림용으로 변경했다. AI는 이번 시즌부터 적용하며 과거 시즌 군주 이름을 재사용하도록 요청했다. 실제 AI 운영 배포는 아직 완료되지 않았다. 아래의 이전 무료량·다음 시즌 대기 조건은 과거 설계 기록이며 최신 지시보다 우선하지 않는다.


2026-10-30 · 운영 중인 전장과 분리해 개발했다. **AI 핵심 로직·검증용 서버 저장소는 구현했으며, 실제 게임 연결과 운영 활성화는 미완료다.** Spark 유지, 유료 함수·예약 작업·실사용량 수집·공식 비용 알림을 새로 배포하지 않았다.

## 계산량을 줄인 방법

- 모든 AI가 회차의 같은 메모리 전장을 사용한다. 판단 함수는 Firebase를 호출하지 않는다.
- 전체 인접 후보를 먼저 훑고 유망한 도시 쌍8개·편성6개 이내만 비교한다.64표본의 사전 선별 뒤512표본 비교, 상위2개는2048표본 재검사한다. 위협은64/128표본으로 좁힌 뒤 보강 후보를 정밀 비교한다. 빠른 선별은 기회를 건너뛸 수 있으나 실제 전투 주사위를 대신 판정하지 않는다.
- 전투 도시·주둔 병력·준비 상태·인접 소유·seed/revision이 같은 평가를 재사용한다. 방어 병력이나 인접 소유가 바뀌면 캐시를 무효화한다.
- 탐색용 복사에는 과거 주사위·사상자 원본을 넣지 않고 요약만 사용한다. 시간 예산이 끝나면 추가 탐색을 보류한다.

## 저장 안전성 — 현재는 검증 전용

`server/ai-state-store.mjs`는 현재 운영 `worlds/*` 경로를 받지 않고 **aiStaging/season-N**에서만 동작한다. Admin용 팩토리도 `demo-*` 프로젝트+DB 에뮬레이터 환경에서만 실행하도록 막았다. 기존 Google 로그인·사용자별 쓰기 권한을 풀지 않았다.

- 상태+요약+새 미처리 사건을 같은 revision 조건부 트랜잭션으로 확정한다. 과거100건의 큰 전투 상세는 별도 records에 둬 상태 트랜잭션에서 제외한다.
- 원본 기록 게시가 중단돼도 outbox의 고정 사건 ID로 복구한다. 공격을 다시 실행하거나 주사위를 바꾸지 않는다. 게시 중 상세 조회는 records/outbox를 통해 같은 원본을 찾는다.
- 원본100건 보존과 오래된 기록 정리는 원래 보존 범위에 맞춘다. 복구 대기가256사건/2MB를 넘으면 추가 확정을 거부한다.
- 임대 token·세대 번호와 revision을 함께 검사한다. 새 실행자가 임대를 받은 뒤 옛 실행자가 계산을 끝내도 덮어쓰지 못한다. 사람 명령이 먼저 도착한 경우 최신 상태에서 최대2회 재시도하며 시간 예산도 누적한다.
- Firebase의 초기 트랜잭션 콜백이 캐시 없는 경로에서null일 수 있는 문제를 실제 에뮬레이터에서 확인해 수정했다. 상태 수신부터 트랜잭션까지 같은 구독을 공유하고 완료 시 해제한다.
- 검증용 작업 팩토리는 기본 비활성이다. Cloud Function 또는 Scheduler를 자동 등록하는 코드는 없다. 비용 보호 코드는 아직 공식 사용량 수집기·이메일 알림에 연결돼 있지 않다.

## 검증 결과

- 기존 게임 포함 단위273개 통과. 기존 Firebase81개+새 격리 저장 검증2개, 전체83개 통과. 빌드 성공.
- 실제 Firebase 에뮬레이터에서 일반 Google 이용자의 검증 저장소 읽기·쓰기 거부, 사람 명령과 revision 충돌, 옛 임대 거부, 게시 중단 후 원본 주사위 복구를 확인했다. 운영 DB로 시험 공격·이동·AI 주입을 하지 않았다.
- 합성 전장6시간, 시작 AI3명:36회차, 공격96회 포함 총223행동, 내부 등장 후 AI9명. 모든 회차는 실제 엔진으로 정산했다. 이 실행의 최대 회차18.1초, 전체 계산237.5초였다. 이후 탐색 복사·캐시를 더 줄였으며 장기 실행 전체를 다시 측정한 것은 아니다.
-90영토에 무장 효과를 넣은 로컬 단일 회차: AI1/5/20명에서 약0.45/7.21/12.62초. 동시 실행 작업과 기기 성능 영향을 받는 참고값이다. 이 균등 포화 배치에서5/20명은 유리한 행동이 없어0행동이었고, 실제 플레이의 행동 빈도 보장으로 해석하지 않는다.
- 합성 상태 JSON은 약198~265KB였다. 네트워크·RTDB 청구량이 아니며 요약·outbox·프로토콜/TLS·다른 이용자의 동기화·기존 서비스 사용량을 모두 포함하지 않는다. 이 수치로 무료0원을 보장하지 않는다.
-72시간 전체 모의 시즌·다중 seed 균형 검증, 운영 Admin SDK 실인스턴스·PC/모바일 실제 AI 화면은 아직 완료하지 않았다. `ai-ui.js`는 선택/표시용 부품만 준비했으며 운영 app.js에 연결하지 않았다.

## 활성화까지 남은 순서

1. 통신 절약 배포 후 대표 활동일 사용량을 확보한다.24시간 경과만으로 자동 승인하지 않는다. 현재 사람 이용량과 AI·함수·로그·빌드·오버헤드를 합산한다.
2. 격리 저장 구조를 실제 신규 시즌에 연결하는 인증된 명령 경로, 기존 사람 명령과의 원자성·호환성, 우승자 선택 UI·지도/랭킹·지난 역사 연결을 마무리한다. 진행 시즌 데이터를 이관·초기화하지 않는다.
3. 공식 사용량 수집·운영자 알림·보호 모드·빌드 보관·최소0/최대1 인스턴스 설정을 준비하고 측정한다. 활성화 검토에서 위험하면 Spark 유지 및 사전 안내.
4. 조건을 통과하면 기존 승인 범위의 Blaze 재연결·서버 배포를 진행하고, **그 뒤 새로 개막하는 시즌**부터 AI를 활성화한다. 현재 시즌에 갑자기 주입하지 않는다. 날짜만으로 활성화를 확정하지 않는다.

따라서 현재를 ‘AI 업데이트 전체 완료’ 또는 ‘사용량만 확인하면 스위치 하나로 운영 가능’이라고 보고하지 않는다. 날짜상 빠르면10월31일 이후 비용 검토를 시작할 수 있으나, 운영 연결·검증과 무료량 여유가 모두 충족돼야 실제 개막 시즌이 확정된다.
