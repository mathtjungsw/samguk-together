# 공격·이동 결과 표시 개선 · 2026-11-02

사용자 상세계획 구현·배포 지시에 따른 작업 기록. 구현·검증·Firebase/사이트 배포·전체 공지 완료. 현재 시즌5부터 적용한다.

## 변경 동작

- 공격·이동/관평 해결은 서버 성공 응답을 받으면 전투 결과/이동 안내를 바로 전달한다. 등록·이름·출발 등 새 전황에 바로 의존하는 흐름은 전황 확인을 기다려 로그인·등록 순서를 보존한다. 기존의 전황+채팅 재조회 대기가 결과 표시를 막지 않는다.
- 서버는 요청·시즌·확정 revision·군주 순번의 작은 메타데이터와 관평 선택 유무를 함께 반환한다. 전체 전장은 응답에 추가하지 않는다.
- 실시간 수신 전황이 이미 확정 revision과 군주 영수증/순번 조건을 만족하면 보충 조회를 생략한다.
- 늦게 오는 전황은 최대500ms 기다린 뒤 전황만 보충 조회한다. 관평 선택은 즉시 조회한다. 실패 시2초·5초 간격 최대2회 추가 확인하며 무한 조회하지 않는다.
- 확인 전에는 다음 저장 명령을 잠근다. 지도 탐색·결과 열람·채팅 열람은 유지하고 상태줄에 ‘결과 저장 완료 · 전황 반영 중…’을 표시한다.
- 확정 후 동기화 대기는 계정/시즌별 최소 메타데이터로 보관한다. 재접속 시 확정 명령을 재전송하지 않고 최신 전황으로 확인한다. 실제 미확인 요청은 기존ID/seq로만 복구한다.
- 늦은 조회가 더 최신 전황을 덮지 않게 하고, 종료된 스토어·다른 시즌의 조회 결과는 반영하지 않는다.
- 일반 공격·이동 후 채팅 강제 재조회는 제거했다. 기존 접속/재연결 조회와 채팅 구독은 유지한다.

## 서버와 비용

서버 사양·최소/최대 인스턴스·동시 요청 설정과 전투 계산 규칙은 유지했다. 반복 요청의 트랜잭션·영수증·기록 저장 순서도 유지했다.

실행시간은 전장 준비/저장 포함 transactionMs, 트랜잭션 콜백 계산 합계 computeMs, 재시도 attempts, 함수 내부 totalMs로 나눠 정상/거절 명령 종류와 함께 최대 약5% 표본으로 기록한다. 군주 이름·계정ID·채팅·전체 전황·인증값은 로그에 추가하지 않는다. 작은 진단 로그에도 소량 비용 가능성이 있으며, 신규 분석 서비스를 추가하지 않았다.

기존 자료만으로 특정 서버 중복 계산을 병목이라고 입증하지 못해 전투 엔진 계산 순서를 임의로 바꾸지 않았다. 표본이 쌓이면 서버 계산/저장 구간을 구분해 후속 최적화할 수 있다. 이번 배포가 전체 서버 응답을 특정 초 이하로 보장한다는 의미는 아니다.

## 검증

- 단위 테스트358개 통과. 신규11개는 지연된 후속 읽기와 무관한 결과 반환, 다음 명령 차단, 실시간 확인 시 보충 읽기0회, 타 군주 revision만으로 잠금해제 금지, 새로고침/레거시 응답 복구, 전황만 조회, 이전 읽기의 최신 전황 덮어쓰기 방지, 로그아웃 중 읽기 폐기 등을 확인했다.
- 로컬 가짜 통신에서 후속 읽기가 영원히 끝나지 않아도 확정 결과 반환이200ms 이내임을 확인했다. 실제 휴대전화·운영 서버의 전체 왕복시간 실측과는 다르다.
- Firebase 에뮬레이터 규칙100개 통과(합계458개), 사이트/서버 빌드와 함수 문법 검사 통과.
- 실제 브라우저 연결을 사용할 수 없어 모바일/PC의 실제 클릭·렌더링 시간과 관평 선택 조작을 직접 측정하지 못했다. 서버 마감10초·전투 연출750ms와 기존 UI 흐름은 유지한다.
- 운영 전장에서 테스트 공격·이동·보상 사용은 하지 않는다.
