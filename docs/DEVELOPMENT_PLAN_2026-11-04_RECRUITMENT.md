# 충원 확률 및 이름 없는 D6 부장 상세 개발계획

작성일: 2026-11-04 · 상태: **구현·검증·배포 완료 / 시즌6부터 새 규칙 적용 대기**

[실행·검증·배포 기록](UPDATE_2026-11-04_RECRUITMENT.md). 아래 내용은 개발 기준과 계획 당시 설명이다. 실제 정책 필드는 `season.recruitmentVersion=2`, 최초 적용 시즌은6으로 구현했다.

## 1. 목적과 확정 범위

정규 충원의 전체 장수 확률 10%는 유지하면서 D12 비중을 높인다. 고유 D6 명단이 소진되어도 D6 추첨은 D6 병력으로 지급한다. 기존 200명 명단·티어·능력과 이미 존재하는 병력은 보존한다.

| 정규 충원 등급 | 기존 기본 확률 | 변경 기본 확률 | 고유 무장 수 | 해당 등급 미등장 후보가 없을 때 |
| --- | ---: | ---: | ---: | --- |
| D4 | 90% | 90% | 해당 없음 | 일반 병사 |
| D6 | 7% | 7% | 110명 | **이름 없는 부장(D6), 특수능력 없음** |
| D8 | 2.5% | **2.2%** | 60명 | 기존처럼 D4 |
| D12 | 0.5% | **0.8%** | 30명 | 기존처럼 D4 |

D20 군주는 정규 충원 대상이 아니다. 변경 전후 D6 이상 등급 추첨 합계는 10%다. 실제 이름 있는 무장 획득률은 남은 후보에 따라 달라진다.

## 2. 정규 충원 처리

1. 기존 충원 예정 시각에 도시의 정원·전투 잠금·시즌 상태를 확인한다.
2. 해당 전장에 고정된 충원 정책과 해당 예정 시각의 기존 내정 효과로 등급 확률을 계산한다.
3. 기존 시드와 추첨 순서를 유지해 D4/D6/D8/D12 등급을 추첨한다.
4. D6 이상이면 해당 등급의 미등장 고유 무장 목록을 구한다. 주둔·복귀 대기·포로 상태는 이미 등장한 것으로 간주한다.
5. 후보가 있으면 기존처럼 그중 한 명을 균등 추첨한다.
6. 후보가 없으면 D6만 이름 없는 부장을 생성하고, D8/D12는 D4로 대체한다. 다른 등급으로 재추첨하지 않는다.
7. 생성 직후 기존 색인·주둔 인원·충원 예정 시각을 갱신한다. 같은 처리 안에서 다음 도시를 계산할 때도 갱신된 명단을 사용한다.

동시 요청은 기존 서버 트랜잭션으로 처리한다. D6 마지막 고유 무장 한 명을 여러 도시에 복제하지 않는다. 기존 미접속 충원·정원 도달 시 정지·내정 및 인연의 추가 D4 지급은 유지한다.

## 3. 이름 없는 D6 병력 정의

- 화면 이름: **이름 없는 부장**. 여러 명 등장 가능하며 각 병력 ID는 고유하다.
- 주사위: 기본 **1~6**, 강화 시 기존 D6 강화 규칙 적용.
- 고유 무장 ID·초상·고유 효과는 부여하지 않는다. 기존 호환 표현인 `legacy:true`를 활용하되 이관된 병력으로 오해하는 화면 문구는 쓰지 않는다.
- 고유 무장 생존 색인을 점유하지 않는다. 이름 있는 D6가 전사하면 이후 충원에서 그 고유 무장이 다시 나올 수 있다. 기존 이름 없는 D6를 자동으로 변환하지 않는다.
- 전투·이동·개인 이동 대기·D4 자리 교환·패전 생존·퇴각·전사·강화 대상/보조 재료는 기존 **D6 등급 규칙**을 따른다.
- 기존 포로 포획은 이름 있는 무장만 대상으로 하므로 이름 없는 D6는 포획 대상이 아니다. 이번 변경으로 포로 범위를 확대하지 않는다.
- 고유 특기·내정 효과·인연 효과는 없다. 기존 일반 D6 판정을 따르는 생존/호위 등과 고유 효과 부재를 구분한다.
- 기본 대기·도시 정원·잔류 병력·전투 잠금은 기존 규칙 그대로다. 새 대기시간이나 별도 정원은 만들지 않는다.
- 이미 보유한 이름 없는 D6와 기존 고유 무장은 변경·삭제·등급 전환하지 않는다.

## 4. 내정 확률 보정

기본 정수 가중치를 기존 `[9000,700,250,50]`에서 새 정책의 `[9000,700,220,80]`으로 변경한다. 단위는 0.01%p이며 합계 10000을 유지한다.

현재 경제 계산의 D6·D8 확률 보너스와 중첩/최댓값 규칙은 유지한다. 보너스는 기존대로 D4에서 차감하고 D12는 기본 0.8%를 유지한다.

| 예시 | D4 | D6 | D8 | D12 |
| --- | ---: | ---: | ---: | ---: |
| 효과 없음 | 90% | 7% | 2.2% | 0.8% |
| D6 확률 +2%p | 88% | 9% | 2.2% | 0.8% |
| D8 확률 +0.5%p | 89.5% | 7% | 2.7% | 0.8% |

이 표는 효과가 실제 발동 조건을 만족할 때의 예시이며 모든 도시에 자동 적용되는 수치가 아니다. 효과 설명의 증가량 자체는 바꾸지 않는다.

## 5. 화면·집계·전황

- 규칙 설명의 기본 확률을 변경한다. 확률 설명과 서버 계산은 같은 정책 함수를 사용한다.
- 명단 요약의 D6 소진 문구를 ‘당첨 시 이름 없는 D6 부장 충원’으로 변경한다. D8/D12 소진 문구는 ‘당첨 시 D4 충원’을 유지한다.
- 고유 무장 명단은 계속 **200명(110/60/30)**이다. 이름 없는 D6는 명단 총수·고유 무장 생존 수·미등장 후보 수에 포함하지 않는다.
- 보유 병력 기준 D6 수·전체 장수 수·내 장수 목록에는 이름 없는 D6를 포함한다. 기존 랭킹 정렬과 영토 우선 기준은 변경하지 않는다.
- 병력 카드/능력 확인에는 공용 초상과 ‘고유 특기 없음’을 표시하고 빈 능력창이나 존재하지 않는 초상 요청이 생기지 않게 한다.
- 이름 없는 D6 충원은 현재 D6 충원과 같은 전황 정책을 따른다. 문장은 ‘○○ 군주의 △△에 이름 없는 부장(D6)이 합류했습니다.’처럼 직책 중복을 피한다.
- 실제 채팅에는 충원 소식을 넣지 않는다. 이번 업데이트 안내만 전체 채팅·전황·접속 공지에 게시한다.

## 6. 적용 시점·저장 호환

**사용자 확정: 다음 시즌부터 적용한다(2026-11-04).** 현재 시즌 적용 추천안은 폐기한다. 이번 단계는 계획 수정이며 구현·배포 완료를 뜻하지 않는다.

- 구현·배포 시 확인한 현재 시즌 번호를 N으로 기록하고, **N+1 시즌과 그 이후 새 시즌**에 새 충원 정책을 적용한다. 이번 계획 수정만을 위해 운영 DB를 조회하거나 수정하지 않는다.
- 현재 시즌 N은 시즌 종료까지 기존 확률 **D4 90% / D6 7% / D8 2.5% / D12 0.5%**와 **D6 명단 소진 시 D4 대체**를 유지한다. 웹/서버가 먼저 업데이트되어도 현재 시즌 규칙은 바뀌지 않는다.
- 새 시즌 생성 시 작은 정책 메타데이터(예: `recruitmentPolicy:{version:2}`)를 전장에 저장한다. 정확한 필드 이름은 구현 시 기존 저장 검증과 함께 확정한다. 정책이 없는 기존 전장은 기존 규칙을 유지한다.
- 시즌 생성·재접속·AI 자동 시즌 개막 등 모든 생성 경로가 같은 적용 시즌 기준을 사용하도록 한다. 배포 중 시즌이 바뀐 경우 임의로 진행 중인 새 시즌 규칙을 소급 변경하지 않고 실제 생성/적용 상태를 확인해 보고한다.
- 충원 정책은 해당 전장에 고정한다. 기존 시즌의 밀린 충원은 기존 정책, 새 시즌의 충원은 새 정책으로 처리한다. 시즌 중간 시각에 따른 혼합 정책 전환은 이번 범위에 필요하지 않다.
- 기존 병력·강화·대기·기록과 종료 시즌·지난 역사는 변경하지 않는다. 새 시즌의 초기화는 기존 시즌 전환 규칙을 따른다.
- 최신 서버와 웹을 준비하고 다음 시즌 생성에 새 정책이 들어가는지 검증한다. 구버전 탭의 요청도 서버가 전장 정책으로 최종 검증하며 새로고침을 안내한다. 클라이언트가 옛 정책으로 계산한 전장 전체를 덮어쓰는 경로가 없는지 확인한다.

## 7. 이번 범위에서 바꾸지 않는 것

- 토벌 보상 등 **고유 무장 수령권**: 정규 충원과 구분한다. 미등장 D6가 없으면 현재처럼 수령권을 보존하며 이름 없는 D6로 자동 소비하지 않는다.
- 중립 소진 후 참가자의 D6 두 명 시작 보너스: 기존 지급/소진 처리 유지.
- 장수 200명 구성·능력·티어, 강화 확률·재료비, AI 공격/등장 규칙, 승리 조건은 유지한다. 플레이어와 AI의 정규 충원에는 같은 새 정책을 적용한다.

## 8. 구현 순서와 주요 파일

1. 정규 충원 정책을 공통 모듈로 분리하거나 기존 정책 모듈에 모아 전장 정책 버전별 기본 가중치와 D6 소진 규칙을 함께 정의한다.
2. `src/engine-next.js`의 `unitTier` 기본값·`spawnRecruit`와 `src/hero-effects-next.js`의 `economy`를 같은 정책에 연결한다. 구형 엔진의 역사적 확률은 일괄 치환하지 않는다.
3. 새 병력의 이름·호환 필드·시각 스탬프·고유 색인을 검증한다. 기존 등급 기반 기능은 재사용한다.
4. `src/field-ui.js` 명단 소진 문구와 관련 규칙 화면·README를 수정한다. 카드·능력창·랭킹은 필요한 부분만 보완한다.
5. 서버 공통 번들·Firebase 저장 검증·다음 시즌 정책 생성 경로와 요청 재시도 호환을 갱신한다. 정책 메타데이터 허용 시 임의 사용자 변경이 불가능하도록 서버 권한으로 제한한다.
6. 단위·서버 통합·화면 검증 후 기존 배포 절차로 서버/웹을 배포하고 현재 시즌 유지·다음 시즌 정책 생성 기준을 확인한다. 배포 완료 후 실제 읽기 확인과 전체 공지를 수행한다.

## 9. 검증 기준

- 정수 경계값 테스트: 새 정책 D4 `[0,9000)`, D6 `[9000,9700)`, D8 `[9700,9920)`, D12 `[9920,10000)`와 각 경계 직전/직후를 확인한다. 정수 가중치를 우선 검증하고 부동소수 오차도 점검한다.
- 내정 보정 후 합계10000, D12 가중치80, D6/D8 증가분과 D4 감소분 일치.
- D6 후보 있음/없음, 마지막 한 명의 같은 시각 다중 도시 충원, D8/D12 소진 대체, 고유 무장 전사 후 재등장.
- 포로·복귀 대기 무장 중복 금지, 이름 없는 D6 여러 명 생성·정규화·저장 재불러오기 성공.
- 이름 없는 D6 전투·이동·포화 도시 교환·퇴각·이름 있는 무장 전용 포획 대상 제외·강화 대상/재료 및 고유 특기/인연 미발동. 기존 보상권은 보존.
- 내 장수 목록·D6 집계는 증가하지만 고유 명단 총수200과 생존 색인은 증가하지 않음. 채팅에는 충원 소식 미출력, 전황 문장 정상.
- 기존/새 시즌 각각의 오프라인 충원 및 시즌 개막 경계, 재시도/재접속에도 중복 지급·재추첨 없음. 종료 시즌과 기존 병력 ID·강화·대기·기록 보존.
- `npm test`, `npm run test:rules`, `npm run build` 통과. 에뮬레이터에서 서버 명령/AI 충원과 저장 검증을 확인한다. PC/모바일의 이름 없는 D6 카드·능력 표시·명단 소진 안내를 합성 전장으로 확인한다.
- 운영 전장에는 검증용 병력 지급·전투·강화를 실행하지 않는다. 배포 전후 현재 시즌 보호 대상 데이터를 대조한다.

## 10. 비용·균형상 영향

별도 서버·새 반복 조회·타이머 없이 기존 충원 처리에서 계산한다. 정책 메타데이터는 기존 전장 읽기로 얻는다. 이름 없는 D6마다 새 고유 초상을 만들거나 다운로드하지 않는다.

D6가 소진되어도 7% 몫의 병력이 D4 대신 D6로 유지되므로 후반 병력의 평균 전투력과 D6 보조 재료 공급이 증가할 수 있다. D6 전황 기록도 계속 생기므로 기존 최근 기록 상한을 유지한다. 사용자 의도에 맞는 규칙 변경이며 이를 이유로 다른 밸런스 수치를 임의 조정하지 않는다.

후보가 충분한 정규 충원1000회 기준 기대값은 D12 5명→8명, D8 25명→22명이다. 무작위 기대값이며 실제 획득 보장이나 실측 결과가 아니다. 이번 계획 단계에서는 게임 코드·운영 데이터·배포를 변경하지 않았다.
