- 위 기본 비용과 성공률40/25/15%는 이전 추천값을 유지한다. 강화에 따른 추가 비용·30분 최초 대기·10분 재시도 간격은 최신 사용자 결정을 반영한다. 확률을 실패 횟수에 따라 자동 상향하거나100%로 만들지 않는다.

## 5. 포로 상태 전이와 공통 통계

`억류 → 반환요청 → 수락/거절/만료`, `억류 → 무상석방`, `억류 → 확률탈출/확정탈출`, `억류 즉시 → 처형`, `억류30분 이후 → 강제등용성공/실패 → 실패 시10분 뒤 재시도 가능`을 공통 상태기계로 처리한다.

- 전사만고유이름예약해제. 소속전환/포로/복귀는 계속예약. 거래/시도/목표보상처리가 같은장수이름을중복확보하지않게 한 전장 트랜잭션 안에서 검증한다.
- 포로별 시도 순번·마지막 등용 시각·다음 등용 시각·마지막 탈출 판정 차수를 서버에 보관한다. 일반 이동·재접속·다른 창·요청ID 교체로 대기를 없애거나 같은 차수를 재추첨하지 못하게 한다.
- 포획, 피포획, 몸값지급/수령, 강제등용성공/실패, 소속이탈, 처형/피처형을 분리한다. 전투처치/전투전사/강화전사/처형전사와 총전사의 관계를 규칙에 명시한다. 기존영토우승순위는 유지한다.
- 포획자가영토0이면 먼저모든포로석방. 원소유가영토0이어도 포로삭제없음. 기존보호복귀/재참가안전성 적용. 시즌종료후에는 처형/등용/반환/보상수령을 금지한다.

### 5.1 확률 탈출과2시간 확정탈출

- **확정탈출:** 포획 시각+2시간. 등용 시도/실패·반환 요청으로 연장하지 않는다.
- **확률 탈출:** 포획30분 경과 시 최초1회, 이후10분마다 각각10%. 포획 후30·40·50·60·70·80·90·100·110분에 최대9차례 판정한다.120분에는 추가10% 추첨 대신 확정탈출한다.
- 시도는 원소유의 접속이나 버튼 조작 없이 자동으로 진행한다. 같은10분 차수의 난수는 서버에서 고정한다. 실패한 차수를 새로고침/수동 정산으로 다시 굴리지 않는다.
- 기존10분 서버 작업과 모든 포로 명령 직전에 지난 예정 차수를 시간순으로 정산한다. 오래 미정산됐다면 차수별로 계산하고 최초 성공 시 남은 추첨을 중단한다. 한꺼번에 여러 탈출 성공/장수 복제를 만들지 않는다.
- **처형·강제등용·몸값 수락 전에 해당 시각까지의 탈출을 먼저 정산**한다.30분 정각에는 첫10% 탈출 판정 후 남아 있는 포로에게 등용을 허용한다.120분 정각에는 확정탈출이 먼저여서 처형/등용/몸값 수락이 불가능하다. 이미 탈출하면 요청 비용은 소모하지 않는다.
- 확정 시각에 원래 계정이 접속하지 않았거나 도시가 가득 찼어도 이름/강화/실패 상태를 보존해 원소유의 보호 복귀 대기로 보낸다. 기존 병력 배치·재참가 정책을 따른다.
- 서버 작업 간격상 실제 배치 갱신은 예정 시각보다 늦을 수 있지만, 예정 탈출 시각 뒤 들어온 처형 요청이 이를 앞질러 성공하지 못하게 한다. 정산된 탈출 시각과 실제 복귀 배치 시각을 구분하고 복귀 대기는 기존 계획대로 실제 배치 확정 시각을 기준으로 적용한다.
-10분 추첨을 위해 새1분 스케줄러나 상시 실행 서비스를 추가하지 않는다. 화면 카운트다운은 로컬에서 계산한다.

### 5.2 포로 전용 탭

- 군령 정보 탭에 **‘포로’ 탭**을 추가한다. 내부에서 ‘내가 잡은 포로/잡혀 있는 내 장수’를 전환한다. 빈 경우에도 탭에서0명과 설명을 확인할 수 있게 한다. 기존 큰 지도/채팅 배치를 덮지 않는다.
- 포로마다 이름·초상·등급·현재 강화·누적 실패·원소유·포획자·포획 시각/경과 시간을 표시한다.
- **확정탈출 예정 시각과 남은 분·초**, **다음10% 탈출 시도 시각과 남은 시간**, 마지막 탈출 판정 결과를 표시한다. 이미 지난 차수가 서버에 미반영됐으면 ‘탈출 정산 확인 중’으로 보여주고 실행 버튼을 확인 없이 활성화하지 않는다.
- **강제등용 최초/다음 가능 시각과 남은 분·초**, 성공률, 기본D4 비용+강화 추가 비용=최종 비용, 최근 시도 결과를 표시한다. 성공 가능한 시간이라는 이유로 자동 시도하지 않는다.
- 내가 잡은 포로에 처형·강제등용·석방·몸값 요청 수락 버튼, 내 장수가 잡혔을 때 반환 요청/대기 상태를 표시한다. 상대 비용 병력 목록처럼 비공개 군령 정보는 보여주지 않는다.
- 시간에 맞춰 버튼을 표시하되 실제 허용 여부는 서버가 탈출/시즌/소유권부터 검사한다. 처리 중에는 해당 요청을 잠그고 결과 유실 시 같은 요청을 재확인한다.
- 실패·탈출·시도 결과는 전황/당사자 알림에 요약하고 모든 실패 추첨을 채팅/전황에 반복 게시하지 않는다. 최신 차수 상태는 포로 정보로 확인한다. 채팅10개/저장50개 정책 유지.

## 6. 무장200명과 티어 재편

기존150명에50명을 추가하고 전체200명의 등급·효과를 함께 검토한다. 후보별200행은 [무장200명 티어·능력 검토표](HERO_200_BALANCE_DRAFT.md)에 기록한다. 사용자 요청7은 ‘무장 확대’ 항목이며 폐기한 이전 개선안7(공격전술)을 되살리는 지시가 아니다.

| 등급 | 기존150명 | 새200명 추천 | 변화 |
| --- | --- | --- | --- |
| D12/S | 30 | **30** | 희소성 유지, 인물·효과 재검토 |
| D8/A | 45 | **60** | +15 |
| D6/B | 75 | **110** | +35, 목표·토벌 보상 풀 확대 |
| 합계 | 150 | **200** | +50 |

- D20은 플레이어 군주이며200명에 포함하지 않는다. D4도 제외한다. 고유 무장은 전장 전체 이름당1명, 처형·전사 후 재등장 가능하다.
- 신규50명의 추천 구성은D12 2명(양호·두예), D8 8명, D6 40명이다. 기존 목록에서는 전위·태사자를D8→D12, 사마사·사마소·종회·노숙을D12→D8, 문앙·진태·조비·원소·동탁을D6→D8로 검토한다. 최종 합계30/60/110과 한글 이름·ID 중복을 문서 검사로 확인했다.
- 자연 충원 확률은 기본D4 90%·D6 7%·D8 2.5%·D12 0.5%에서 출발한다. 무장 수 증가만으로 이 확률을 자동 상향하지 않는다. 기존 미등장 후보 고갈 시D4 대체를 자연 충원에 유지한다. 보상은 별도 확률표를 굴리지 않고 미등장D6 풀에서 직접 추첨한다.
- 카탈로그와 효과 정책을 새 버전으로 분리한다. 기존150명 분기, 무장 번호별 하드코딩, 주사위 면수 상한, 도감 개수, 역할 자격, AI 이름 충돌 검사, 보안 규칙을 전수 검색한다. 진행 중인 시즌의 카탈로그는 덮어쓰지 않는다.
- 기존150명의ID·이름은 유지하고 신규는hero-151~hero-200을 사용한다. 능력은 인연·강화·포로 규칙까지 합쳐 조정한다. 설명과 실제 계산을 함께 변경한다.
- D6는 작은 단일 효과, D8는 중간 전술 효과, D12는 역할이 분명한 상위 효과를 기준으로 한다. 상위 티어는 주사위 평균도 높으므로 추가 효과까지 무조건 강화하지 않는다. 인연이 없는 장수도 단독으로 쓸 가치가 있게 한다.
- 점수 계열은D6 보통+1/조건부+2, D8 +2/조건부+3~4, D12 +3~5 정도를 기준으로 검토한다. 이는 일괄 변환 공식이 아닌 총효과 평가 기준이다. 검토표는 기존150명 중11명 티어 변경,14명 효과 조정, 신규50명 효과를 제안하며 다른 장수는 기존 효과와 공통 규칙의 조합을 검사한다.
- 충원은 가장 짧은 주기 하나만 적용하고 최저8분을 기준으로 한다. 정규 충원 추가는 최대3회당1명 수준을 기준으로 검토한다. 내정 확률 보정은 담당 도시 또는 명시된 인접1도시에만 적용한다. 기존 생존·호위는 횟수와 퇴각 조건을 유지한다.
- 고정 최저 눈과 강화 최저 눈은 큰 값을 적용하고, 재굴림은 강화된 유효 눈 범위를 사용한다. 인연의D4 보호는 실제 전사 후보만 구하며 몸값·강화 재료·처형을 보호하지 않는다.
- 신규 포획/강제등용 확률 상승 특기는 최초 버전에서 추가하지 않는다. 공통 포로 정책으로 효과를 비교할 수 있게 한다.
- 기존 자체 초상·사용 허용 자료를 재사용하고, 신규50명은 이름·등급을 읽기 좋은 공통 초상으로 우선 지원한다. 별도50장 생성이나 상용 게임 초상 복제를 필수 선행 조건으로 삼지 않는다.

## 7. 추가 개발·검증 작업

1.200명 명단·한글 이름·ID·티어·효과 정책을 검토표에서 확정하고 새 카탈로그를 구현한다. 진행/과거 시즌은 기존 버전으로 재생한다.
2.보상 슬롯·부분 수령·고유 이름 예약을 구현한다. 목표·토벌 한도와 일관된 수령 영수증을 사용한다.
3.몸값 재료 다도시 선택, 처형·등용 상태 전이, 시간·횟수 제한과AI 처리를 구현한다. 서버가 모든 추첨·지불·소유권 전환을 확정한다.
4.인연 기준ID는 유지하되 변경한 티어·능력과 함께 예상 승률·실제 전투·AI 평가를 맞춘다.
5.D6 후보0/1/2명, 동시 보상·충원·등용, 처형 후 동일 인물 재등장, 부분 수령 재요청, 포로 강화 보존, 원소유 변경·재포획, 몸값 부족,3도시 재료와 잔류,즉시 처형·30분·10분 재시도·2시간·시즌 마감 경계, 각 탈출 차수1회 및 중복 요청 거절을 검사한다.
6.200명 효과마다 발동·미발동/경계 검사를 작성한다. 표준 편성의 강화0/1/3, 인연 중첩, 승자 피해, 역할 자동 배정을 확인한다. 시뮬레이션으로 특정 무장 필수화와 과도한 점수 조합을 찾아 추천값을 조정한다. 아직 실행하지 않은 결과를 균형 검증 근거로 표시하지 않는다.
7.보안 규칙256KiB 한도(기존 약254KB), 정적 카탈로그·ID 검증 방식, 타무장 복제·시도 순번/대기 삭제·보상 한도 우회 거절을 확인한다. 명단 전체를 매 명령마다 새로 내려받지 않고 서버 번들과 정적 브라우저 카탈로그를 사용한다.
8.이번에는 계획 문서만 갱신한다. 구현 지시 후 검증·배포하고 진행 시즌 다음 새 시즌부터 적용한다. 운영 병력을 강등·교체·삭제하거나DB를 변경하지 않는다.
