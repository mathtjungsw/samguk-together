# 추가 서버 속도 개선 · 실행 계획

사용자 직접 ‘추천한 것도 반영해서 개발 배포’ 지시에 따른 현재 시즌 적용 범위다. 앞선 카드 제거는 배포·공지 완료했다. 추가 서버 속도 개선도 구현·검증·배포·현재 시즌 활성화·전체 공지 완료했으며, [최종 기록](UPDATE_2026-11-02_SERVER_SPEED.md)을 따른다.

1. 활성 전장에는 전투 요약과 상세 버전만 남기고 상세는battleRecords의 불변 버전 경로로 분리한다. 기존 전투 결과·병력·시즌 정보는 보존한다.
2. 트랜잭션에는 새 상세와 전달 대기 정보를 함께 저장한다. 확정 후 하나의 원자적 업데이트로 외부 상세 저장과 전달 대기 제거를 수행한다. 실패해도 원본은 전달 대기에 남고 상세 조회가 대기 원본을 읽을 수 있게 한다. 다음 명령/AI 작업에서 전달을 재시도한다. 응답 후 실행 보장 없는 작업은 두지 않는다.
3. 최신100개 전황의 상세만 보관하도록 빠진 기록의 불변 상세 버전 삭제도 대기에 함께 기록한다. 다른 명령의 새 기록을 삭제하지 않는다.
4. 전체 데이터 읽기가 필요한 전투/충원/포로 판정은 현재 상태의 같은 원자 트랜잭션에서 유지한다. 과거 주사위 상세만 분리한다. 구 형식 기록을 읽는 폴백과 로컬 기록 캐시는 유지한다.
5. 반복되는 군주별 영토·병력 전체 순회를 한 번의 집계로 바꾼다. 입력/출력 검증과 무작위 결과는 유지한다. 동일 저장/난수의 결과 대조와 로컬 시간을 확인한다.
6. campaignOrder만 CPU1로 상향하고 동시 요청1·최소0·최대1은 유지한다. 다른 함수 CPU와 상시 대기는 유지한다. 실행 단가는 올라갈 수 있고 실제 총비용은 시간 감소에 따라 달라진다.
7. 기존 전장은 명시적 이관 전까지 원래 형식을 유지하는 준비 서버·규칙을 배포하고, 새 상세 형식을 이해하는 사이트를 확인한 뒤 현재 전장의 분리를 활성화한다. 진행 중 전장을 백업하고 ETag/트랜잭션 보호하에 기록 형식만 이관한다. 게임 필드 일치·상세 개수/내용 보존·전황 피드를 확인한다. 이전 화면은 갱신 안내를 제공하며 상세 조회에는 최신 화면 사용이 필요하다.
8. 단위·스토어/기록 조회·Firebase 규칙/전달 실패/동시 저장 검증과 빌드 후 공개 파일·CPU 설정·현재 저장 크기를 확인한다. 실제 운영에서 테스트 공격은 하지 않는다. 표본 없는 운영 속도를 보장하지 않는다. 완료 후 전체 채팅·전황·접속 안내를 게시한다.

상시대기1개와 함수 동시 요청 증가는 이번 범위에 포함하지 않는다. 현재 규모에서 우선 필요한 데이터·계산 절감과 명령 함수만의 CPU 개선을 적용한다.
