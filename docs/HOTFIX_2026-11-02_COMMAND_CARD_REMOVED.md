# 이전 명령 확인 카드 제거 · 임무 삭제 재점검

사용자의37707.jpg 화면 보고와 직접 삭제 지시에 따른 구현. 구현·단위 검증 완료, 서버 규칙 검증·배포 진행.

## 화면과 동작

- 영토·명령 화면의 ‘확인하지 못한 이전 명령이 있습니다.’ 카드와 ‘이전 명령 결과 확인’ 버튼, 전용 클릭 처리를 제거했다.
- commandCampaignHTML은 토벌령과 이미 지급된 받을 보상만 표시한다. 임무 탭·목표 조회·선택·진행률·신규 임무 보상 발급은 제공하지 않는다.
- 남아 있는 이전 임무 요청은 기존 차단 목록으로 로컬에서 정리하며 서버 호출·보상 발급을 수행하지 않는다. 기존 임무 API 차단과privateMissions 읽기/쓰기 거절은 보안·구버전 호환을 위한 차단 규칙으로 유지한다.
- 이미 지급된 수령권과 보유 장수·병력은 보존한다. 임무를 실행해서 신규 보상을 만드는 경로는 없다.
- 실제 공격·이동 등의 미확인 요청은 별도 카드 대신 뒤에서 자동 확인한다. 최신 전황을 먼저 읽고 영수증/순번으로 완료·재실행 불가 여부를 판단하며, 필요한 경우에만 기존 요청ID/seq를 그대로 사용한다.
- 자동 확인 중에는 다음 저장 명령을 차단하고 기존 상태줄에 ‘처리 상태 확인 중…’을 표시한다. 진행 중인 명령과 자동 복구는 겹쳐 실행하지 않는다.
- 자동 확인은 요청별 최대3회, 완료 후2초/5초 간격을 적용한다. 연결 끊김·전황 미준비·창 닫힘에서는 새 복구를 시작하지 않는다. 계속 확인되지 않으면 기존 상단 ‘다시 연결’에서 조회·확인을 수동 재개할 수 있다.
- 새로운 요청 번호로 공격을 재발행하거나 확인되지 않은 요청을 버리는 방식으로 카드를 없애지 않았다.

## 검증

- 단위365개 통과. 추가7개는 임무 잔여 요청의 무호출 정리, 영수증 우선 확인, 동일ID/seq 유지,3회/간격 제한, 실행 중·중복 복구 억제, 조회 중 종료 시 호출 차단, 오프라인 요청 보존을 확인한다.
- UI 회귀 검증은 실제commandCampaignHTML 출력을 사용해 임무 UI/이전 명령 카드가 없고 기존/토벌 수령권이 남는지 확인한다.
- 앞선 결과 우선 표시·명령 확정/동기화 보호·로그인 등록 순서 테스트를 함께 통과했다.
- 실제 브라우저의 모바일 조작은 직접 확인하지 못했다. 공개 배포 파일에서 카드/버튼 문자열·전용 이벤트 처리 제거와 최신 코드를 별도로 확인한다.
- 운영 전장에서 테스트 공격·이동·보상 수령이나 게임 데이터 삭제를 하지 않는다.

자동 복구는 예외 상황에서만 제한적으로 작동한다. 정상 명령마다 추가 요청을 반복하는 주기 조회를 추가하지 않는다. 서버 사양·게임 규칙은 변경하지 않는다. 더 큰 서버 속도 개선은 별도 대기 개선안이다.
