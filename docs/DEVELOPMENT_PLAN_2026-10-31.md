# 삼국 · 함께 천하 — 통신 절감·AI 행동·세력 식별 상세계획

작성일: 2026-10-31. **상태: 계획 작성 완료 / 구현·검증·배포 대기.**

이 문서는 현재 대기 중인 개선안 전체의 최신 실행 명세다. 이전에 완료한 지도·전투·무장·시즌·채팅 개편을 다시 구현하지 않는다. 2026-10-31의 성급한 로컬 구현은 이미 취소됐으며 이번 작업은 문서만 작성한다. 다음 ‘업데이트/구현’ 지시 이후 진행한다.

## 1. 범위와 적용 시점

| 묶음 | 목적 | 다음 구현 지시 이후 적용 |
| --- | --- | --- |
| AI 장기 대치 해소 | 유리한 싸움만 기다리며 수비·이동을 반복하는 정체 완화 | 진행 중 시즌 AI부터 안전하게 이관 |
| 기록 로컬 저장 | 새로고침·재접속 때 같은 전투와 결과 재다운로드 줄이기 | 새 화면 접속 이후 |
| AI 조회 절감 | 이름·시작 수를 구하기 위한 과거 자료 반복 조회 제거 | 운영 함수 업데이트 이후 |

지도 인접, 주둔 한도, 충원 확률, 장수 효과, 사람 전투, 시작 보호, 시즌 승리 조건은 유지한다. 시작 AI 수는 직전 우승자1~5명 선택·미선택3명, 다음10분 예약 실행 시 배치하는 현행 방식을 유지한다. 진행 중2시간 내부 등장도 유지한다. 비용 발생 가능성만으로 개발을 멈추거나 AI·요금제를 바꾸지 않는다.

## 2. AI 장기 대치 해소

### 2.1 일반 공격과 모험 공격

일반 공격은 사람 상대80%, 중립·AI 상대75%, D20 출진90%의 현행 기준을 출발점으로 유지한다. 기존 `idleRounds` 기반 완화는 ‘공격하지 않은 경과시간’으로 대체한다. 수비·이동·부활은 시간을 초기화하지 않는다. 일반 공격 문턱은 공격 없이1시간마다5%p 완화, 최대15%p 및 최저65%; D20 편성은 계속90%다.

일반 공격 후보가 없으면 아래 별도 모험 공격을 평가한다. 표의 승률은 기존처럼 오차를 감안한 보수적 추정치이며, 공격 추첨 확률과 전투 승률은 서로 다르다.

| 실제 공격 없이 지난 시간 | 모험 후보 최소 승률 | 이번 기회에 출진할 추첨 확률 |
| --- | --- | --- |
| 1시간 미만 | 없음 | 모험 공격 안 함 |
| 1시간 이상~2시간 미만 | 50% | 20% |
| 2시간 이상~3시간 미만 | 40% | 35% |
| 3시간 이상 | 30% | 50% |

- AI당 모험 추첨은30분에 최대1회다. 10분 예약마다 재추첨하지 않고 `nextRiskAt`을 저장한다. 정각 전후 연속 추첨도 막는다.
- 후보가 없는 회차는 공격하지 않는다. 후보를 확보하고 추첨한 경우 성공·실패 모두 다음 추첨까지30분 기다린다.
- 추첨 성공 시 후보 중 승률·획득 가치·방어 여력을 평가해1곳을 선택한다. 후보마다 여러 번 추첨해 확률이 부풀지 않게 한다.
- 모험 출진 편성에는 D20을 넣지 않는다. D20을 제외한 편성으로 승률을 다시 계산한다.
- 인간 영토2개 이하 공격 금지, 인접·보호·행동 대기·전투 잠금·출발지 최소 주둔·특기 조건은 유지한다. 모험 공격도 전투 결과를 보정하지 않는다.
- 출발지에는 기존 규칙상 최소1명을 남기며, 상대가 즉시 점령할 위험이 큰 출발지는 기존 방어 위험 검사로 제외한다. 점령 후 반격 위험은 모험 후보의 감점 요소로 사용한다. 일반 공격의 안전한 점령지 조건 때문에 낮은 승률 후보가 전부 사라지지 않도록 별도 평가 경로를 둔다.
- 유효 후보가 없거나 추첨에 계속 실패하면 장기간 공격하지 않을 수 있다. 강제 공격·강제 패배·공격 보장은 도입하지 않는다.

### 2.2 판단 순서와 실행 안전성

1. 미결 전투·관평 호위 등 필수 정산을 먼저 한다.
2. 출발지 안전 검사로 위험 도시를 제외하고 일반 공격을 찾는다.
3. 일반 공격이 없고 시간 조건이 맞으면 모험 공격 후보와 추첨을 평가한다.
4. 공격을 못 하면 기존 수비 보강→후방 보급→장수 이동·부활을 평가한다. 이동을 먼저 반복해 공격 평가가 영원히 밀리는 구조를 없앤다.
5. 군주당 영토 행동 최대2회·독립 장수 이동1회, 전체 판단 시간 예산은 유지한다. 모험 공격은 한 추첨 기회에 최대1회다.

실제 적/중립 도시 공격 명령이 확정됐을 때만 `lastAttackAt`을 갱신한다. 승리·패배 모두 포함하고 아군 이동은 제외한다. 전투가 관평 선택 대기로 넘어가도 공격 시작은1회로 센다.

기존 AI는 마지막 공격 시각을 현재 보관 기록에서 확실히 찾을 수 있으면 복원한다. 찾지 못하면 업데이트 시각부터 대기시간을 시작해 배포 즉시 일제히 위험 출진하지 않게 한다. 새 AI는 등장 시각부터 센다. `lastAttackAt`, `nextRiskAt`, 정책 버전을 서버 AI 메타데이터에 저장하고 기존 JSON 문자열 저장·사람의 변경 금지를 유지한다.

출진 추첨은 서버 비밀 키 기반 난수로 전투 주사위와 다른 용도의 키를 사용한다. 명령ID·추첨 기회ID를 고정해 중복 실행·재시도·저장 충돌로 다시 뽑지 않는다. 추첨 결과와 행동은 동일한 revision 조건 저장에 포함하고 충돌 시 다른 사람의 최신 명령을 덮지 않는다. 추첨 자체를 전체 채팅에 쌓지 않고 실제 전투는 기존 전황에 남긴다.

## 3. 기록의 로컬 영구 저장

### 3.1 저장 대상·흐름

IndexedDB를 사용한다. 현재 메모리12건 캐시를 보조 캐시로 유지하면서 새로고침·브라우저 재실행 후에도 기록을 재사용한다.

| 자료 | 조회·저장 방식 | 갱신 기준 |
| --- | --- | --- |
| 확정 전투 상세 | 유효한 로컬 사본 우선, 없을 때 해당 전투1건만 조회 | 시즌·전투ID·확정 버전 |
| 지난 시즌 최종 지도·랭킹 | 작은 결과 버전 확인 후 유효 캐시 사용 | 결과 전용 버전/해시 |
| 진행 중 관평 선택·미결 전투 | 확정 기록 캐시 대상에서 제외 | 기존 최신 서버 정산 |
| 현재 영토·병력·소유권·명령 | 로컬 기록 캐시로 대체하지 않음 | 기존 서버 최신 상태 |

키는 Firebase 프로젝트/DB·계정·시즌·기록ID·캐시 형식 버전을 포함한다. 테스트/운영, 계정, 시즌이 섞이지 않게 한다. 화면에는 필요 시 ‘기기에 저장된 기록’ 정도만 표시하며 플레이에 불필요한 저장 기술 설명을 넣지 않는다.

### 3.2 정정·실패·용량 처리

- 서버에 작은 기록 버전 메타데이터를 둔다. 전투는 기존 전황 요약과 함께 확정 버전이 전달되게 해, 로컬 적중 시 별도 상세 조회를 하지 않는다.
- 시즌 결과는 결과 자체가 바뀔 때만 버전을 갱신한다. 단순 접속·업데이트 공지·전장 revision 변화로 매번 결과 캐시가 무효화되지 않게 한다.
- 기존 기록에 버전이 없으면 최초1회 원본을 검증하고 서버에서 버전을 채우는 이관 절차를 사용한다. 결과 원문을 매번 받아 해시를 계산하는 방식은 피한다.
- 운영 정정은 원본·버전을 함께 바꾸고 캐시를 무효화한다. 캐시 형식 버전이 바뀌거나 값이 손상되면 해당 사본만 버리고 서버에서 다시 받는다.
- 권장 초기 제한은 계정별 최근 전투100건·시즌 결과12개, 기기 전체 합계10MiB·최대90일이다. 최근 열람 기록을 우선 보관하며 한도를 넘으면 오래된 로컬 사본만 삭제한다. 서버 기록 삭제 정책은 바꾸지 않는다.
- 시크릿 모드·저장 차단·용량 초과·타임아웃은 일반 서버 조회로 복구한다. 저장 실패로 기록 열람이나 게임 진입을 막지 않는다.
- 새 기기·브라우저 초기화 후에는 처음부터 다시 내려받는다. 서버 보관 범위를 벗어난 기록도 검증 가능한 로컬 사본이 있으면 기기에 보관된 기록으로 열람할 수 있도록 정정/폐기 버전 정책을 함께 검토한다. 무효화 여부를 확인할 수 없는 사본을 ‘서버 확인 완료’로 표시하지 않는다.
- 서버 확인을 못 하면 현재 전장 명령은 기존처럼 막는다. 확정 기록의 오프라인 열람은 ‘최신 확인 안 됨’을 표시하고 결과를 현재 플레이에 사용하지 않는다.

## 4. AI의 반복 조회 절감

### 4.1 이번 구현의 필수 절감

현재 함수는10분마다 과거 결과최대12개, 직전 시즌의 결과를 포함한 season과 players, 투표를 읽는다. 최신 이름 정책에서는 과거 사용자 이름 자체가 필요 없다.

1. AI 이름 후보는 검증된 정적 인물 목록으로 배포한다. 과거 사용자 이름을 구하기 위한 결과 조회를 제거한다.
2. 다음 시즌 시작 수는 개막 전 우승자의 선택으로 계속 갱신하고, 첫 배치가 확정된 뒤에는 현재 시즌 AI 메타데이터의 확정 수를 재사용한다.
3. 기존 시즌의 최초 이관 때만 필요한 이전 우승자·투표를 좁게 조회한다. 지난 지도·랭킹 전체를 시작 수 계산용으로 반복 다운로드하지 않는다.
4. 기존 `namePool`의 옛 사용자 이름은 새 인물 목록 정책으로1회 이관한다. 서버 재시작·콜드 스타트 때도 원래 자료를 읽지 않도록 작은 확정 운영 자료를 DB에 보관한다. 함수 메모리 캐시는 추가 최적화일 뿐 유일한 근거로 쓰지 않는다.
5. AI 전체가 하나의 현재 전장을 공유하는 구조와10분 주기·최소 인스턴스0을 유지한다. 이름 변경 때문에 실행 주기나 인스턴스를 늘리지 않는다.

### 4.2 현재 전투 상세 조회의 구조 검토

현재 서버는 한정된 현재 시즌 스냅샷과 revision 조건 트랜잭션으로 병력을 안전하게 보존한다. 전투 상세를 읽지 않고 요약만 조립한 뒤 전체 전장을 덮어쓰면 원본 전투를 지울 수 있으므로 금지한다.

이번 구현에서 먼저 과거 반복 조회 제거의 읽기 횟수·바이트를 측정한다. 현재 스냅샷에서 전투 상세가 차지하는 비중과 읽기/저장 경로를 별도로 검토해 결과를 기록한다. **이번 범위는 이 구조 검토까지 필수이며, 원본 전투의 별도 저장소 이관은 자동 실행 범위에 넣지 않는다.** 실제 분리가 필요하면 기존·신규 화면 호환, 명령 원자성, 상세 보존과 복구를 포함한 후속 상세계획으로 제시한다. 통신 절감을 이유로 기존 저장 안정성을 희생하지 않는다.

## 5. 세력 색상 배정

### 5.1 사용자 확정 규칙

- 기존 기본15색을 유지한다. 영토를 보유한 세력이 사용하는 색만 ‘사용 중’으로 센다.
- 새 세력·재참가·신규 AI는 빈 기본 색부터 배정한다. 여러 개면 고정된 기본 색 순서로 선택한다.
- 기본15색을 모두 쓰면 새로운 색을 생성해 배정한다. 기본15색보다 가독성이 낮아져도 허용하지만 같은 색을 중복 배정하지 않는다.
- 기본 색이 비면 다음 배정이 그 색을 먼저 사용한다. 이미 추가 색으로 플레이 중인 군주는 자동으로 기본 색으로 바꾸지 않는다.
- 탈락자의 옛 색은 예약하지 않는다. 재참가 시 빈 기본 색→새 색 순으로 다시 배정한다. 영토가 있는 상태에서 D20만 죽는 것은 색 반환 사유가 아니다.

### 5.2 저장·기존 중복 보정

색은 저장된 공통 식별자를 사용한다. 각 클라이언트가 소유 영토 변화마다 색을 다시 계산해 서로 다르게 보이거나 전투 때마다 색이 바뀌는 방식은 쓰지 않는다.

- 기본 색은0~14 슬롯, 추가 색은15 이상 고유 슬롯과 공통 색 생성 규칙으로 표현한다. 실제 저장 필드는 구현 시 기존 `color` 검증·구버전 화면을 확인해 호환 필드/정책 버전으로 확정한다.
- 신규 참가의 이름 등록과 실제 첫 영토 배정은 구분한다. 영토를 얻는 시점에 색을 확정하며, 동시에 참가한 세력은 같은 revision의 원자 저장 검증으로 중복 배정을 막는다.
- 기존 중복은 배포 전 백업 후1회 보정한다. 같은 색이면 먼저 참가한 현존 세력(동률UID순)이 유지하고 나머지는 빈 기본 색→추가 색을 배정한다. 겹치지 않은 기존 색은 가능한 한 유지한다.
- 색을 이미 반납한 탈락자는 범례·순위에서 ‘탈락/영토 없음’ 표시를 사용해 현재 세력과 혼동을 줄인다. 다시 시작하면 새 배정 색을 쓴다.
- 지도 면색·도시 깃발·군주 범례·랭킹은 동일한 해석 함수를 쓴다. 선택/출발/목표 강조는 세력색과 구분한다.
- 무한 AI 등장에 고정 팔레트 나머지 연산을 사용하지 않는다. 새 색은 결정적인 생성 순서로 RGB 중복을 검사하고 부족하면 명도·채도를 확장한다. 비슷한 색은 인접 경계·군주명·클릭 강조로 보조한다. 시각적으로 모든 세력을 완벽히 구분하는 것은 보장하지 않는다.
- 지난 시즌 완료 결과는 당시 소유권·색을 보존한다. 신형 추가 색도 최종 결과에 저장·재현한다.

## 6. AI 군주 이름 변경 — 최신 사용자 지시 반영

사용자의 최종 지시로 **황건적과 삼국연의 일반 인물을 모두 제외**하고, 중국사·한국사의 건국 군주만 사용한다. 표기는 `AI왕건`, `AI유방`, `AI이성계`와 같은 AI 접두어 형식이다. 기존150인 무장 및 그 별칭은 계속 제외한다.

실행 기본 명단은 중국14명·한국10명, 총24명이다. 왕건·유방·이성계·영정·주몽·양견·온조·이연·박혁거세·조광윤·김수로·주원장·대조영·쿠빌라이·견훤·유수·궁예·사마염·단군왕검·유유·소도성·소연·진패선·누르하치. 단군 등은 건국 전승으로 구분하고 자료와 함께 기록한다. 인물별 국가·건국 대상·원문명·근거는 데이터 파일에 남긴다.

미사용 인물을 먼저 쓰며, 중국·한국 이름이 모두 등장하도록 후보를 섞는다. 전체 후보를 소진하면 `AI왕건2`처럼 번호로 확장한다. 현존 세력과 전체 이름이 같으면 건너뛰고, 향후150인 명단이 바뀌어도 차집합을 다시 검사한다.

현재 영토가 있는 기존 AI의 표시 이름과 살아 있는 D20 이름도1회 바꾼다. UID·생성 순서·병력ID·소유권·통계·대기시간은 보존한다. 확정된 지난 시즌 결과 및 과거 전투/채팅 원문은 소급 변경하지 않는다. 과거 사용자 이름 재사용·AI 표기 숨김·삼국연의 일반 인물 후보는 모두 최신 지시로 대체됐다.

## 7. 저장·권한·운영 절차

- 운영 백업을 확보하고 시험 전장/에뮬레이터에서 이관한다. 병력·소유권·이전 시즌 결과를 초기화하지 않는다.
- AI 메타데이터는 사람 클라이언트가 바꾸지 못하도록 유지한다. 사람 명령 후에도 서버 전용 새 필드가 보존돼야 한다.
- 캐시 버전 메타데이터는 Google 로그인한 게임 참가자가 읽을 수 있는 최소 경로만 연다. 원본 기록의 기존 접근 제한은 유지한다.
- 색 배정 필드는 등록/시작/AI 배치·이관에 필요한 경우만 변경하도록 제한한다. 임의로 남의 색을 바꾸는 명령은 거부한다.
- RTDB 규칙 파일은 현재256KiB 제한에 가깝다. 규칙을 생성 도구에서 수정하고 크기·구문·기존 권한 회귀 검사를 통과시킨다. 크기 때문에 검증식을 단순 삭제하거나 쓰기 권한을 넓히지 않는다.
- 배포 순서는 호환 읽기/규칙 준비→백업·멱등 이관→서버 함수→신형 화면→공지로 구성한다. 구버전은 최신 화면 갱신을 안내하며 새 색/메타데이터를 지우는 저장을 막는다. 세부 순서는 실제 호환성 검사 결과로 확정한다.
- 단일 이관을 다시 실행해도 이름·색이 재추첨되거나 병력이 늘지 않게 이관ID/정책 버전을 저장한다.
- 전체 채팅·전황·접속 알림에 통합 공지를1회 전달한다. 매 AI 추첨·캐시 적중을 채팅으로 전송하지 않는다.
- 실패 시 새 기능 경로만 이전 호환 경로로 되돌리고 정상 플레이 저장을 덮어쓰지 않는다. 캐시를 잃어도 원본 서버 기록을 복구할 수 있어야 한다.

## 8. 작업 순서

1. 기존 저장·이름·색 분포와 캐시/AI 조회 경로의 기준값을 확인한다. AI 인물 후보와150인 제외 검사를 준비한다.
2. 로컬 기록 저장 모듈·작은 버전 경로·기록 조회를 구현하고 정상/실패/정정 흐름을 검증한다.
3. AI 이름을 정적 후보로 교체하고 시작 수·이름 목록의 반복 조회를 없앤다. 현재 전투 상세 스냅샷 분리의 효과·위험을 검토해 별도로 기록한다.
4. 색 배정 공통 함수·저장 호환·원자 검증과 기존 중복 보정 절차를 구현한다.
5. AI 공격 시간·모험 후보·30분 추첨·난수·이관을 구현한다. 기존 전투 엔진은 재사용한다.
6. 전체 단위·Firebase 규칙·혼합 클라이언트·합성 전장·PC/모바일 검증을 수행한다.
7. 승인된 실행 단계에서만 운영 배포·이관·통합 공지·서버 로그와 배포 자산 확인을 수행하고 결과를 보고한다.

## 10. 결정 상태

사용자 확정: 네 개선 묶음의 계획 작성, AI 모험 출진 제안 수치, 기본15색 우선 및 빈 색 재사용, 추가 색 허용, 150명 밖 건국 군주의 `AI왕건` 형식, 이번 이름 요구의 상세계획 직접 포함.

구현 기본안: 저장 한도·기간, 기존 AI 이름1회 교체, 인물 후보 소진 시 번호, 중복 색 유지 우선순위, 공격 시간 이관, 메타데이터 세부 경로. 이는 본 문서의 구체적인 실행 추천이며 실제 적용 완료가 아니다. 사용자는 구현 지시 전에 수정할 수 있다.

이번에 하지 않은 작업: 게임 코드 수정, 운영 DB 쓰기·이관, 함수·보안 규칙·사이트 배포, AI 전투 규칙 적용. 문서 변경에 게임 테스트를 새로 실행하지 않는다.
