# 병력 확률 강화·AI 일반 공격 완화 상세 개발계획

작성일: 2026-11-02 · 대상: samguk-online · 단계: **구현·검증 진행 중**.

사용자는 친구10~15명이 즐기는 게임을 원한다. 강화 조작을 단순하게 하고 기존 영토·병력·지난 시즌 기록을 보존한다. 사용자가 본 상세계획의 개발·배포를 승인했다. 추천 수치는 이번 구현의 기본값으로 채택하며, 강화와 AI 일반 공격 완화 모두 다음 시즌인 시즌5부터 적용한다. 현재 시즌4와 과거 기록은 보존한다.

## 2. 강화 효과와 전투 계산

### 2.1 기본 규칙

- 대상: 내 도시의 D4·D6·D8·D12·D20 병력. 이름 없는 기존 동급 병력도 동일하게 취급한다.
- `최소 눈 = 1 + 강화 단계`, `최대 눈 = 주사위 면수`. 추천 상한+3은 모든 등급에 동일하다.
- 기본 굴림은 최소~최대의 정수 중 **동일 확률**로 선택한다. 예를 들어 D4+1은2·3·4가 각각1/3이다. 기존1~4를 굴린 뒤1을2로 바꾸는 방식은 사용하지 않는다.

| 등급 | 0강 | +1 | +2 | +3(추천 상한) |
| --- | --- | --- | --- | --- |
| D4 | 1~4 | 2~4 | 3~4 | 4 고정 |
| D6 | 1~6 | 2~6 | 3~6 | 4~6 |
| D8 | 1~8 | 2~8 | 3~8 | 4~8 |
| D12 | 1~12 | 2~12 | 3~12 | 4~12 |
| D20 | 1~20 | 2~20 | 3~20 | 4~20 |

- 기대 눈은 단계마다0.5씩 오른다. 주사위 면수나 장수 티어는 변하지 않는다.
- 공격과 수비에 모두 적용한다. 공격90% 감산·동점 수비 승리·특기 가산 상한·접전 피해/생존 계산 순서는 유지한다. 강화로 바뀐 기본 눈이 기존 전투 계산의 입력이 된다.
- 재굴림도 강화된 기본 범위에서 굴린다. 승률 계산 worker·AI 승률 추정·실제 전투·전투 상세 표시에 같은 공통 굴림 함수를 사용한다.
- **추천 특기 처리:** 강화는 기본 굴림의 최솟값이다. 이후 적 특기의 눈 감소는 기존처럼 적용하여 강화 최솟값 아래로 내려갈 수 있다. 화면에 ‘기본 굴림 범위, 특기 적용 후 변경 가능’을 표시한다. 강화로1이 나오지 않으면 ‘1이 나올 때’ 발동하는 기존 특기는 발동하지 않는다. 이 상호작용은 규칙에 설명한다.
- 기존 관평 선택 대기 전투의 이미 고정된 주사위는 다시 굴리지 않는다. 과거 전투는 당시 저장된 원래 눈·점수로 재생한다.

### 2.2 성공·실패·전사

1. 강화 시도에 필요한 재료를 먼저 검증한다. 실행이 저장되면 성공/실패 모두 재료를 소모한다.
2. 성공: 강화 단계+1. **누적 실패는 초기화하지 않는다.**
3. 실패: 강화 단계1 하락, 최저0. 누적 실패+1. 0강에서도 실패는 누적된다.
4. 누적 실패가 해당 등급의 한도에 도달하면 즉시 전사한다. 대상은 사라지고, 재료도 반환하지 않는다. 실패 횟수는 임의 추첨이 아니라 결과에 따라 정확히1씩 증가한다.

| 대상 | 누적 실패 한도 추천 | 의미 |
| --- | ---: | --- |
| D4 | 3회 | 세 번째 실패 시 전사 |
| D6 | 4회 | 네 번째 실패 시 전사 |
| D8 | 5회 | 다섯 번째 실패 시 전사 |
| D12 | 6회 | 여섯 번째 실패 시 전사 |
| D20 | 8회 | 여덟 번째 실패 시 전사 |

예: D6가+2·실패2/4일 때 실패하면+1·실패3/4. 그다음 시도가 성공하면+2·실패3/4로 유지한다. 이후 한 번 실패하면 네 번째 실패이므로 전사한다.

- 이동·퇴각·복귀 대기·접속 종료·성공으로 실패 누적을 초기화하지 않는다.
- 강화 전사는 전투 패배가 아니다. 관평 호위·장수 불사/탈출 특기·접전 생존·중립전 D20 탈출을 적용하지 않는다. 전투 승리/패배 통계나 상대 처치 수를 올리지 않는다.
- 대상의 강화 전사는 죽은 병력 수에 포함하고 원인을 ‘강화 전사’로 구분한다. 재료 소모는 전사/상대 처치에 포함하지 않는다.
- 이름 있는 장수가 전사하면 heroIndex 예약과 담당 배정을 정리하고, 기존 규칙대로 다시 등장할 수 있다. 다시 등장한 새 병력은0강·실패0회다.
- D20 전사 시 군주 생존 표시·rulerId를 갱신한다. 영토가 남으면 계속 플레이하고 기존 병력 교환 부활을 허용한다. 부활한 새 D20은0강·실패0회다. 군주 이름·영토·현재 전적을 초기화하지 않는다.

## 3. 성공률·재료·행동 대기 추천

| 강화 시도 | 성공률 추천 |
| --- | ---: |
| 0→+1 | 80% |
| +1→+2 | 60% |
| +2→+3 | 40% |

| 대상 등급 | 0→+1 재료 D4 | +1→+2 재료 D4 | +2→+3 재료 D4 |
| --- | ---: | ---: | ---: |
| D4 | 1명 | 2명 | 3명 |
| D6 | 2명 | 3명 | 4명 |
| D8 | 3명 | 4명 | 5명 |
| D12 | 4명 | 5명 | 6명 |
| D20 | 5명 | 6명 | 8명 |

- 기본 재료는 같은 도시에 있는 행동 가능한 **0강 D4**다. 강화 대상 자신은 제외한다. 등급별 재료 수는 불필요한 재화 체계 없이 선택의 비용을 만드는 추천안이다.
- 사용자 추가 요구에 따라 성공률 보조 재료로 같은 도시의 D6·D8·D12를 선택할 수 있다. **추천은 기본 D4 재료에 추가하는 방식**이며, 한 번에 세 등급 중1명만 추가한다. 상승량은 D6+10%p, D8+20%p, D12+30%p를 추천한다. 사용자 확정 상한100%를 적용하여 `최종 성공률=min(100%, 기본 성공률+보조 상승량)`으로 계산한다. 대체 재료 환산이나 여러 명 중첩은 이번 추천에 넣지 않는다.

| 강화 시도 | 보조 재료 없음 | D6 1명 추가(추천) | D8 1명 추가(추천) | D12 1명 추가(추천) |
| --- | ---: | ---: | ---: | ---: |
| 0→+1 | 80% | 90% | 100% | 100% |
| +1→+2 | 60% | 70% | 80% | 90% |
| +2→+3 | 40% | 50% | 60% | 70% |

- 보조 재료도 성공·실패 모두 소모한다. 대상과 같은 병력은 재료로 선택할 수 없고 D20은 재료로 쓰지 않는다. 복귀 대기·전투 잠금·행동/개인 이동 대기 중인 D6·D8·D12는 제외한다. 100%인 시도는 확정 성공하여 단계만 상승하고 누적 실패는 늘지도 초기화되지도 않는다. 재료는 정상 소모한다.
- 이름 없는 D6·D8·D12와 이름 있는 무장 모두 수동 선택할 수 있게 계획하되 자동으로 이름 있는 무장을 넣지 않는다. 이름·등급·강화·실패 누적·고유 효과와 소모 사실을 선택 화면에 명시한다. 소모된 이름 있는 무장은 기존 전장 전체 중복 예약을 해제하여 다시 등장할 수 있게 한다. 재료 소모는 전사/상대 처치로 집계하지 않는다.
- 자동 기본 재료 선택은 대상 제외→0강 D4→행동 가능→도시 도착/생성 순서로 고정한다. 보조 재료는 사용자가 직접 지정하고 요청에 실제 재료 ID를 포함한다. 직전 전황이 바뀌어 재료가 다르면 서버가 재검증하고 임의의 다른 병력을 대신 소모하지 않는다. 보조 무장의 정원/담당 효과가 사라져 남은 병력이 정원을 넘게 되는 선택은 사전에 거절하며 병력을 조용히 삭제하지 않는다.
- **도시 행동 대기와 관계없이 강화할 수 있고 성공·실패 모두 도시 행동 대기를 변경하지 않는다.** 대상 병력 행동 대기는 끝나야 하며 장수는 개인 이동 대기도 끝나야 한다. 전투 잠금·호위 선택 중인 도시/병력은 강화할 수 없다.
- **재료 소모 후 강화 대상 외에도 주둔 병력1명을 남긴다.** 대상이 전사해도 도시가 무병력 상태가 되지 않게 사전 차단한다. 시스템이 병사를 새로 생성해 메우지 않는다.
- 저장된 시도는 성공·실패 모두 도시 행동을 소모하지 않는다. 도시의 기존 actionReadyAt을 그대로 보존하고 단축도 연장도 하지 않는다. **강화 후 대상에게 행동·이동 대기를 새로 부여하지 않는다.** 생존 대상과 다른 병력의 기존 readyAt·moveReadyAt을 그대로 보존한다. 따라서 재료와 강화 조건이 충족되면 같은 병력을 다음 요청으로 다시 강화하거나 기존 전투/이동 조건에 따라 바로 출전시킬 수 있다. 강화가 기존 대기를 단축하거나 전투 잠금을 해제하는 수단이 되어서는 안 된다.
- 한 번에1명·1단계 시도한다. 연속 자동 강화·일괄 다중 추첨은 도입하지 않는다. +3 대상·재료 부족·대기 중·시즌 종료 요청은 재료/실패 횟수 변화 없이 거절한다.

## 4. 화면·전황·통계

- 도시 군령에 ‘병력 강화’ 버튼을 추가하고 강화 창에서 병력과 다음 단계·기본 굴림 범위·기본/보조 반영 최종 성공률·재료 인원·누적 실패/한도·남은 실패 여유를 보여준다. 보조 재료는 ‘없음/D6/D8/D12’를 선택하고 실제 병력을 지정한다. ‘도시 행동 소모 없음·강화 후 신규 대기 없음·기존 대기 유지’를 표시하며 최종100%는 ‘확정 성공’으로 안내한다.
- 장수 상세·내 장수 목록에는 예: ‘장비 D12 +2 · 기본3~12 · 실패2/6’를 표시한다. 장수 상세에서 현재 도시의 강화 창으로 바로 연결한다.
- D4는 주둔 화면이 길어지지 않게 강화 단계·실패 횟수별로 묶는다. 묶음의 ‘1명 강화’는 대상1명의 ID를 고정하고 선택 내용을 명시한다. 전황 자동 갱신으로 다른 병력으로 바뀌지 않게 한다.
- 다음 실패가 전사라면 실행 버튼 근처에 해당 대상의 전사 위험을 분명하게 표시한다. 성공률과 생존 확률을 혼동시키지 않는다. 결과 애니메이션으로 다시 추첨하지 않는다.
- 결과는 ‘성공 +1→+2 / 실패 +2→+1·누적3/6 / 누적6/6 도달·전사’로 보여준다. 서버 응답 전에는 확정 성공을 표시하지 않는다. 연결 실패 시 같은 요청의 결과 확인을 우선한다.
- 공격/수비 편성·장수 초상·D4 묶음에 강화 단계를 표시한다. 전투 상세는 기본 굴림 범위·원래 눈·특기 적용 후 눈을 구분한다. 랭킹의 기본 순위는 영토 우선으로 유지한다.
- 강화 결과와 강화 전사는 전황에 남긴다. 전체 채팅은 실제 대화·공지·업데이트만 유지하며 매 강화 결과를 보내지 않는다. 현재 전황100건·전체 채팅50건 보관 정책을 늘리지 않는다.
- 같은 등급 전사 대상 선택·D4 구조 비용 등 자동 소모에서 강화 병력이 어떻게 취급되는지 명시한다. 추천은 기존 낮은 등급 우선에 이어 **같은 등급에서는 낮은 강화 단계 우선**, 이후 기존 정렬을 사용한다. 강화 단계가 생존 추첨 확률을 직접 올리지는 않는다.

## 5. 저장·서버·확률 안전성

- 병력별 `enhanceLevel`, `enhanceFailures`를 보관한다. 누락 값은0으로 읽는다. ID·면수·이름·영웅 ID·고유 효과·생성/도착 시간은 강화 때문에 새로 만들지 않는다.
- 강화 규칙 버전과 성공률·재료·실패 한도는 시즌 설정으로 고정한다. 진행 중 시즌에서 수치가 조용히 바뀌지 않게 한다. 과거 시즌과 전투 기록은 당시 버전을 보존한다.
- Google 인증된 본인만 강화 요청 가능하다. 서버 함수가 최신 대상·재료·대기·주둔·실패 한도·시즌 상태를 검증하고, 도시/병력/통계/담당/영웅 예약/결과를 한 전장 트랜잭션으로 저장한다.
- 서버 비공개 난수로 판단한다. 요청 ID와 군주별 강화 순번을 사용하여 재접속·중복 클릭·응답 유실로 같은 시도가 다시 추첨되거나 재료가 두 번 소모되지 않게 한다. 트랜잭션 충돌 재시도도 같은 난수 기회를 사용하며 미저장 시도는 실패 횟수에 넣지 않는다.
- 최근 요청 결과를 제한 수로 보관하고, 결과가 보관 범위를 벗어난 오래된 순번 요청은 재실행하지 않고 거절한다. 무제한 요청 기록을 현재 전장에 계속 쌓지 않는다.
- 보상 서버에서 확인한 첫 실행의 빈 로컬 캐시 문제를 다시 만들지 않도록 전장 준비→원자 처리→구독 해제 순서를 재사용한다. 실패/시간 제한/성공 모두 구독을 정리한다.
- 클라이언트가 강화 단계·실패 횟수를 임의로 높이거나 지우는 저장을 차단한다. 이동·배열 순서 변경·퇴각·복귀 대기·D4 자리 교환에서도 원래 병력 ID의 값을 보존하도록 서버 규칙을 검증한다.
- 강화 전투를 이해하지 못하는 구버전 화면은 잘못된 전투를 저장하지 못하게 막는다. 기존 featureVersion6·150인 판별 분기를 무작정7로 올리지 않고, 강화 규칙 버전과 명령의 지원 버전을 검사하는 호환 차단을 설계한다. 새 화면을 먼저 준비한 뒤 강화 기능을 연다.
- 기존 함수/DB를 활용한다. 강화 창은 현재 전황에서 후보를 표시하고 클릭할 때만 서버 요청한다. 군주별/도시별 전체 DB 반복 읽기·새 상시 작업·새 유료 서비스를 추가하지 않는다. 호출·원자 저장에 따른 비용 가능성은 안내하되 비용만으로 승인된 작업을 중단하지 않는다.

## 6. AI 일반 공격 완화

| 실제 공격 없이 지난 시간 | 사람 상대 | 중립·AI 상대 |
| --- | ---: | ---: |
| 1시간 미만 | 75% | 70% |
| 1~2시간 | 70% | 65% |
| 2~3시간 | 65% | 60% |
| 3시간 이상 | 60% | 60% |

- `max(60%, 기본 기준 - min(15%p, 경과 시간당5%p))`를 사용한다. D20 포함 편성은 항상90% 이상이다.
- 이동·수비·부활·강화는 ‘마지막 실제 공격 시각’을 초기화하지 않는다. 실제 공격이 저장된 경우에만 갱신한다.
- 사람 영토2개 이하 보호, AI는1영토도 공격 가능, 출발지 최소 잔류·방어 안전·행동 대기·보호 시간·전투 잠금 검사를 유지한다. 승률 문턱을 넘었다고 반드시 공격하는 것은 아니다.
- 모험 공격은 운영 규칙 그대로다: 1/2/3시간 후보 최소 승률50/40/30%, 출진 추첨20/35/50%, AI별30분 최대1회, D20 제외. 삭제한4시간80%·승률 하한 해제와25/40/55% 상향은 포함하지 않는다.
- 내부 등장4시간, 판단10분, 시작 AI1~5명을 유지한다. AI의 전투 예상에는 강화된 병력을 반영하되 AI가 스스로 강화하는 새 행동은 추가하지 않는다.

## 7. 작업 순서와 적용

1. 사용자 확정 규칙을 기준으로 최대 단계·성공률·재료·실패 한도·적용 시점 추천안을 확정한다.
2. 강화 규칙·기본 주사위 굴림·실패 누적/전사·통계·요청 순번의 순수 함수를 만든다.
3. 기본 전투·승률 worker·AI 평가·재굴림과 연결한다. 기존 특기150명의 관련 조건 및 과거 기록 재생을 검증한다.
4. 인증 서버 함수·원자 저장·중복 방지·시즌/구버전 호환·DB 규칙을 구현한다. 생성된 보안 규칙256KiB 한도를 자동 검사하고 기존 검사를 없애서 맞추지 않는다.
5. 도시 강화 창·장수/D4 표시·결과·전황·통계를 구현하고 PC/모바일에서 확인한다.
6. AI 일반 공격 문턱을 변경하고 보호 규칙·경계 시각·실제 공격 시간 갱신을 회귀 검사한다.
7. 단위·Firebase 에뮬레이터·실제 서버 SDK 첫 실행·중복/충돌/연결 실패·저장 보존을 확인한다. 운영에서는 승인 없이 다른 사람의 강화나 전투를 대신 실행하지 않는다.
8. 호환 서버/규칙→화면→기능 개방 순으로 승인된 업데이트를 배포한다. 무관한 영토·병력은 초기화하지 않는다. 다음 시즌부터 적용하는 경우 시즌 생성 함수의 정책을 고정하고 종료/재개막도 검증한다.
9. 실제 적용 결과를 전체 채팅·전황·접속 알림에 안내하고 README/규칙 설명을 갱신한다. 아직 실행하지 않은 기능을 적용 완료로 표시하지 않는다.
